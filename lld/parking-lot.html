01 Requirements & Scope

Functional Requirements
  • Park vehicle — accept a vehicle at an entry gate, allocate the best available slot, issue a timestamped ticket.
  • Unpark vehicle — accept a ticket at an exit gate, compute the fee, vacate the slot, return change.
  • Multi-floor support — the lot has N floors; each floor has M slots of varying types (COMPACT, REGULAR, LARGE).
  • Ticket generation — every entry produces a unique ticket with vehicleId, slotId, floorNumber, and entryTime.
  • Fee calculation — on exit, fee = f(duration, vehicleType, pricingStrategy); strategy is configurable at runtime.
  • Display available slots — query per floor and per slot type; used by overhead signage and mobile apps.
Non-Functional Requirements
  • Thread-safe slot allocation — hundreds of vehicles may arrive concurrently; no two threads may book the same slot.
  • Extensible vehicle types — adding a new vehicle type (e.g., Bus) must not touch existing allocation code.
  • Extensible pricing — swap from hourly to flat-rate or add surge pricing by injecting a different strategy.
  • Single ParkingLot instance — Singleton: there is only one lot; all gates share the same state.
  • Low latency on park/unpark — each operation should complete in O(F×S) where F=floors and S=slots per floor.

ParkingSlot — with AtomicBoolean for thread safety
import java.util.concurrent.atomic.AtomicBoolean;

public class ParkingSlot {
    private final String  slotId;
    private final int     floorNumber;
    private final SlotType slotType;
    private final AtomicBoolean isOccupied = new AtomicBoolean(false);
    private volatile Vehicle parkedVehicle;

    public ParkingSlot(String slotId, int floorNumber, SlotType slotType) {
        this.slotId       = slotId;
        this.floorNumber  = floorNumber;
        this.slotType     = slotType;
    }

    /**
     * Atomically marks the slot as occupied by the given vehicle.
     * Uses CAS (Compare-And-Swap) so only one thread can succeed.
     *
     * @return true if occupation succeeded, false if slot was already taken
     */
    public boolean occupy(Vehicle vehicle) {
        if (isOccupied.compareAndSet(false, true)) {
            this.parkedVehicle = vehicle;
            return true;
        }
        return false;   // another thread beat us to it
    }

    /**
     * Frees the slot. Called by unpark flow only after fee is collected.
     */
    public void vacate() {
        this.parkedVehicle = null;
        isOccupied.set(false);
    }

    public boolean isAvailable()      { return !isOccupied.get(); }
    public String  getSlotId()        { return slotId; }
    public int     getFloorNumber()   { return floorNumber; }
    public SlotType getSlotType()     { return slotType; }
    public Vehicle getParkedVehicle() { return parkedVehicle; }

    @Override
    public String toString() {
        return "Slot[" + floorNumber + "-" + slotId + " " + slotType + "]";
    }
}

public class Floor {

    private final List<ParkingSlot> slots;

        this.floorNumber = floorNumber;
        this.slots       = new ArrayList<>(slots);

        return slots;
    }

        return slots.stream()
                .filter(s -> s.getSlotType() == type && s.isAvailable())
                .collect(Collectors.toList());
    }

    public long countAvailableSlots(SlotType type) {
        return slots.stream()
                .filter(s -> s.getSlotType() == type && s.isAvailable())
                .count();
    }

    public long countTotalAvailable() {
        return slots.stream().filter(ParkingSlot::isAvailable).count();
    }
}

04 Strategy Pattern: Slot Allocation

Why Strategy? If we put slot-selection logic inside ParkingLot, it becomes one giant if-else: "Is it a bike? Go to floor 1. Is it a truck? Find a large slot. Is it peak hour? Use a different floor…" Every new allocation rule means opening ParkingLot.java — a file that has nothing to do with the rule. Strategy extracts the algorithm into its own class family.
Strategy Interface
import java.util.List;
import java.util.Optional;

public interface SlotAllocationStrategy {
    /**
     * Given all floors and the incoming vehicle, return the best available slot.
     * Returns Optional.empty() if no slot is found (lot is full for this type).
     */
    Optional<ParkingSlot> findSlot(List<Floor> floors, Vehicle vehicle);
}
NearestSlotStrategy — scan floors top-down, first available match
import java.util.List;
import java.util.Optional;

public class NearestSlotStrategy implements SlotAllocationStrategy {

    @Override
    public Optional<ParkingSlot> findSlot(List<Floor> floors, Vehicle vehicle) {
        SlotType required = mapVehicleToSlotType(vehicle.getVehicleType());

        for (Floor floor : floors) {
            // First: try the exact slot type match
            Optional<ParkingSlot> exact = floor.getSlots().stream()
                    .filter(s -> s.getSlotType() == required && s.isAvailable())
                    .findFirst();
            if (exact.isPresent()) return exact;

            // Fallback: allow smaller vehicles to use a larger slot
            if (vehicle.getVehicleType() == VehicleType.BIKE) {
                Optional<ParkingSlot> larger = floor.getSlots().stream()
                        .filter(s -> s.getSlotType() == SlotType.REGULAR && s.isAvailable())
                        .findFirst();
                if (larger.isPresent()) return larger;
            }
            if (vehicle.getVehicleType() == VehicleType.CAR) {
                Optional<ParkingSlot> larger = floor.getSlots().stream()
                        .filter(s -> s.getSlotType() == SlotType.LARGE && s.isAvailable())
                        .findFirst();
                if (larger.isPresent()) return larger;
            }
        }
        return Optional.empty();
    }

    private SlotType mapVehicleToSlotType(VehicleType type) {
        return switch (type) {
            case BIKE  -> SlotType.COMPACT;
            case CAR   -> SlotType.REGULAR;
            case TRUCK -> SlotType.LARGE;
        };
    }
}
TypeBasedStrategy — strict type enforcement, no cross-type parking
import java.util.List;
import java.util.Optional;

public class TypeBasedStrategy implements SlotAllocationStrategy {

    @Override
    public Optional<ParkingSlot> findSlot(List<Floor> floors, Vehicle vehicle) {
        SlotType required = switch (vehicle.getVehicleType()) {
            case BIKE  -> SlotType.COMPACT;
            case CAR   -> SlotType.REGULAR;
            case TRUCK -> SlotType.LARGE;
        };

        return floors.stream()
                .flatMap(floor -> floor.getSlots().stream())
                .filter(slot -> slot.getSlotType() == required && slot.isAvailable())
                .findFirst();
    }
}
Open/Closed in action: To add an "EV priority" strategy that assigns the nearest charging-capable slot, you create EVPriorityStrategy implements SlotAllocationStrategy and inject it. ParkingLot.java is never touched. This is precisely the answer that scores full marks in an LLD interview.

05 Strategy Pattern: Pricing

PricingStrategy Interface
public interface PricingStrategy {
    /**
     * Calculates the fee for a completed (or completing) parking session.
     * The ticket's exitTime must be set before this is called.
     *
     * @param ticket  the ticket with entry/exit time and vehicle info
     * @return        fee in dollars
     */
    double calculateFee(Ticket ticket);
}
HourlyPricingStrategy — rate varies by vehicle type
import java.time.temporal.ChronoUnit;
import java.util.EnumMap;
import java.util.Map;

public class HourlyPricingStrategy implements PricingStrategy {

    // Rates in dollars per hour
    private static final Map<VehicleType, Double> HOURLY_RATES = new EnumMap<>(VehicleType.class);

    static {
        HOURLY_RATES.put(VehicleType.BIKE,  1.00);
        HOURLY_RATES.put(VehicleType.CAR,   2.00);
        HOURLY_RATES.put(VehicleType.TRUCK, 4.00);
    }

    @Override
    public double calculateFee(Ticket ticket) {
        if (ticket.getExitTime() == null) {
            throw new IllegalArgumentException("Exit time not set on ticket " + ticket.getTicketId());
        }

        long hours = ChronoUnit.HOURS.between(ticket.getEntryTime(), ticket.getExitTime());
        // Minimum 1-hour charge
        hours = Math.max(1, hours);

        double rate = HOURLY_RATES.getOrDefault(
                ticket.getVehicle().getVehicleType(), 2.00);

        return hours * rate;
    }
}
FlatRatePricingStrategy — one fixed fee per vehicle type per visit
import java.util.EnumMap;
import java.util.Map;

public class FlatRatePricingStrategy implements PricingStrategy {

    private static final Map<VehicleType, Double> FLAT_RATES = new EnumMap<>(VehicleType.class);

    static {
        FLAT_RATES.put(VehicleType.BIKE,  5.00);
        FLAT_RATES.put(VehicleType.CAR,  10.00);
        FLAT_RATES.put(VehicleType.TRUCK, 20.00);
    }

    @Override
    public double calculateFee(Ticket ticket) {
        return FLAT_RATES.getOrDefault(ticket.getVehicle().getVehicleType(), 10.00);
    }
}
Runtime swappability: Because both strategies share the PricingStrategy interface, the ParkingLot can switch from hourly to flat-rate dynamically — e.g., flat-rate on weekends — with a single setter call: lot.setPricingStrategy(new FlatRatePricingStrategy()).

06 Factory Pattern: Vehicle Creation

Why Factory? Without it, every entry-gate call site does: if (type == CAR) new Car(...) else if (type == BIKE) new Bike(...). The day you add ElectricBus, you hunt down every such block. Factory centralizes object construction in one place — all callers are insulated from subtype details.
VehicleFactory
import java.util.UUID;

public class VehicleFactory {

    private VehicleFactory() {} // prevent instantiation

    /**
     * Creates the correct Vehicle subtype based on VehicleType.
     * Auto-generates a UUID vehicle ID.
     *
     * @param type         VehicleType discriminator
     * @param licensePlate the vehicle's plate (must be unique in practice)
     * @return             a fully constructed Vehicle
     * @throws IllegalArgumentException for unknown vehicle types
     */
    public static Vehicle createVehicle(VehicleType type, String licensePlate) {
        String vehicleId = UUID.randomUUID().toString();
        return switch (type) {
            case CAR   -> new Car(vehicleId, licensePlate);
            case BIKE  -> new Bike(vehicleId, licensePlate);
            case TRUCK -> new Truck(vehicleId, licensePlate);
            // Adding ElectricBus? Add one case here — nowhere else.
        };
    }
}
Factory Method vs Abstract Factory: This is a static factory method — a single factory that creates one product family. If we had different factories for Sedan, SUV, and MotorCycle (sub-families), that would be Abstract Factory. Knowing this distinction lands extra points in LLD interviews.

07 Singleton: ParkingLot

Thread-Safe Double-Checked Locking Singleton
import java.time.LocalDateTime;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;
import java.util.concurrent.locks.ReentrantLock;

public class ParkingLot {

    // ── Singleton boilerplate ──────────────────────────────────────────────────
    private static volatile ParkingLot instance;

    private ParkingLot() {}

    public static ParkingLot getInstance() {
        if (instance == null) {
            synchronized (ParkingLot.class) {
                if (instance == null) {
                    instance = new ParkingLot();
                }
            }
        }
        return instance;
    }

    // ── State ──────────────────────────────────────────────────────────────────
    private List<Floor>              floors;
    private SlotAllocationStrategy   slotAllocationStrategy;
    private PricingStrategy          pricingStrategy;

    // ConcurrentHashMap: multiple threads can read active tickets simultaneously
    private final Map<String, Ticket> activeTickets = new ConcurrentHashMap<>();
    private final AtomicLong          ticketCounter  = new AtomicLong(1);

    // Lock that guards the find-then-occupy critical section
    private final ReentrantLock allocationLock = new ReentrantLock();

    // ── Initialization (call once after getInstance()) ─────────────────────────
    public void initialize(List<Floor> floors,
                           SlotAllocationStrategy allocationStrategy,
                           PricingStrategy pricingStrategy) {
        this.floors                  = floors;
        this.slotAllocationStrategy  = allocationStrategy;
        this.pricingStrategy         = pricingStrategy;
    }

    // ── Core: park ─────────────────────────────────────────────────────────────
    /**
     * Parks a vehicle: finds a slot, occupies it atomically, issues a ticket.
     *
     * @return the issued Ticket, or Optional.empty() if the lot is full
     */
    public Optional<Ticket> park(Vehicle vehicle) {
        allocationLock.lock();
        try {
            Optional<ParkingSlot> slotOpt = slotAllocationStrategy.findSlot(floors, vehicle);
            if (slotOpt.isEmpty()) {
                return Optional.empty();   // lot full for this vehicle type
            }

            ParkingSlot slot = slotOpt.get();
            boolean occupied = slot.occupy(vehicle);
            if (!occupied) {
                // Slot was grabbed by another thread between findSlot and occupy
                // Retry once with full search (simplified — production would loop)
                return park(vehicle);
            }

            String ticketId = "T-" + String.format("%05d", ticketCounter.getAndIncrement());
            Ticket ticket   = new Ticket(ticketId, vehicle, slot, LocalDateTime.now());
            activeTickets.put(ticketId, ticket);

            System.out.printf("[PARK]   %s → %s  ticket=%s%n", vehicle, slot, ticketId);
            return Optional.of(ticket);

        } finally {
            allocationLock.unlock();
        }
    }

    // ── Core: unpark ───────────────────────────────────────────────────────────
    /**
     * Unparks a vehicle: computes fee, vacates slot, closes ticket.
     *
     * @return the closed Ticket with fee populated
     */
    public Ticket unpark(String ticketId) {
        Ticket ticket = activeTickets.get(ticketId);
        if (ticket == null) {
            throw new IllegalArgumentException("No active ticket found: " + ticketId);
        }
        if (ticket.isClosed()) {
            throw new IllegalStateException("Ticket already closed: " + ticketId);
        }

        LocalDateTime exitTime = LocalDateTime.now();
        ticket.closeTicket(exitTime, 0.0);            // set exit time first
        double fee = pricingStrategy.calculateFee(ticket);
        ticket.closeTicket(exitTime, fee);             // re-close with actual fee

        ticket.getSlot().vacate();
        activeTickets.remove(ticketId);

        System.out.printf("[UNPARK] %s ← %s  fee=$%.2f  duration=%s→%s%n",
                ticket.getVehicle(), ticket.getSlot(), fee,
                ticket.getEntryTime(), exitTime);
        return ticket;
    }

    // ── Queries ────────────────────────────────────────────────────────────────
    public long getAvailableCount(SlotType type) {
        return floors.stream()
                .mapToLong(f -> f.countAvailableSlots(type))
                .sum();
    }

    public void displayAvailability() {
        System.out.println("=== Parking Lot Availability ===");
        for (Floor floor : floors) {
            System.out.printf("  Floor %d: COMPACT=%d  REGULAR=%d  LARGE=%d%n",
                    floor.getFloorNumber(),
                    floor.countAvailableSlots(SlotType.COMPACT),
                    floor.countAvailableSlots(SlotType.REGULAR),
                    floor.countAvailableSlots(SlotType.LARGE));
        }
    }

    // ── Setters for runtime strategy swap ─────────────────────────────────────
    public void setSlotAllocationStrategy(SlotAllocationStrategy s) {
        this.slotAllocationStrategy = s;
    }
    public void setPricingStrategy(PricingStrategy p) {
        this.pricingStrategy = p;
    }
}
volatile is mandatory on the instance field. Without it, the CPU may reorder instructions and a second thread could observe a partially-constructed ParkingLot object. volatile establishes a happens-before relationship — the full construction is visible before the reference is published.

08 Concurrency Deep Dive

The Double-Booking Problem
Thread 1 (Car A)                          Thread 2 (Car B)
────────────────                          ────────────────
findSlot()  → slot 1-A is FREE            findSlot()  → slot 1-A is FREE
                                          occupy(1-A) → isOccupied = true  ✓
occupy(1-A) → reads isOccupied = true     ← BOTH see FREE before either sets true!
              sets isOccupied = true       ← Both "win" with non-atomic check+set
              parkedVehicle = Car A        ← Car B is already there → CRASH

                  ↑ THIS IS THE BUG WITHOUT ATOMIC OPS
Fix 1: AtomicBoolean.compareAndSet — CAS operation
// Inside ParkingSlot
public boolean occupy(Vehicle vehicle) {
    // compareAndSet(expected=false, update=true)
    // Only ONE thread can succeed — the one that finds isOccupied==false
    // and atomically flips it to true. All others get false back.
    if (isOccupied.compareAndSet(false, true)) {
        this.parkedVehicle = vehicle;
        return true;   // this thread wins
    }
    return false;      // slot was taken — caller must retry
}
AtomicBoolean alone is NOT enough. There is still a TOCTOU (Time-of-Check-to-Time-of-Use) gap between findSlot() reading isAvailable() and the later occupy() call. Between those two calls, another thread may sneak in. The solution: wrap the entire find + occupy in a single ReentrantLock.
Fix 2: ReentrantLock wrapping find + occupy (used in ParkingLot.park)
private final ReentrantLock allocationLock = new ReentrantLock();

public Optional<Ticket> park(Vehicle vehicle) {
    allocationLock.lock();       // ← CRITICAL SECTION STARTS
    try {
        // findSlot + occupy are now atomic as a unit
        Optional<ParkingSlot> slotOpt = slotAllocationStrategy.findSlot(floors, vehicle);
        if (slotOpt.isEmpty()) return Optional.empty();

        ParkingSlot slot = slotOpt.get();
        slot.occupy(vehicle);    // cannot fail now — we hold the lock

        String id     = "T-" + ticketCounter.getAndIncrement();
        Ticket ticket = new Ticket(id, vehicle, slot, LocalDateTime.now());
        activeTickets.put(id, ticket);
        return Optional.of(ticket);

    } finally {
        allocationLock.unlock(); // ← CRITICAL SECTION ENDS — always released
    }
}
Why ConcurrentHashMap for activeTickets?
  • Multiple exit gates may call unpark() simultaneously on different tickets — ConcurrentHashMap allows these concurrent reads without full locking.
  • Segment-level locking inside ConcurrentHashMap means only same-bucket operations block each other.
  • We still use the allocationLock for the park path to protect the find+occupy unit.
Interview answer: "I use AtomicBoolean.compareAndSet() on the slot as a lock-free CAS operation, and I additionally wrap findSlot + occupy in a ReentrantLock to eliminate the TOCTOU window. The CAS is the last-line defense; the lock prevents even reaching a contested slot in the first place."

09 Walking a Flow

Happy Path: Car ABC-123 parks and then exits
  1. Car arrives at Entry Gate. Gate calls VehicleFactory.createVehicle(VehicleType.CAR, "ABC-123") → returns Car[ABC-123] with a UUID.
  2. Gate calls ParkingLot.getInstance().park(car).
  3. ParkingLot acquires allocationLock (no contention — proceeds immediately).
  4. Calls slotAllocationStrategy.findSlot(floors, car). NearestSlotStrategy scans Floor 1 → finds slot 1-A (REGULAR, isOccupied=false) → returns it.
  5. Calls slot.occupy(car) → compareAndSet(false, true) → succeeds → parkedVehicle = car.
  6. Creates Ticket: ticketId="T-00001", vehicle=Car[ABC-123], slot=1-A, entryTime=10:00:00.
  7. Puts ticket in activeTickets map: key="T-00001".
  8. allocationLock released. Gate prints ticket to driver. Driver parks.
  9. [2 hours pass]
  10. Driver arrives at Exit Gate with ticket T-00001.
  11. Gate calls ParkingLot.getInstance().unpark("T-00001").
  12. ParkingLot looks up ticket in activeTickets map → found.
  13. Sets exitTime = 12:00:00 on ticket.
  14. Calls pricingStrategy.calculateFee(ticket) → HourlyPricingStrategy: hours=2, rate=$2/hr → fee=$4.00.
  15. Calls slot.vacate() → isOccupied.set(false), parkedVehicle=null. Slot is now available for the next car.
  16. Calls ticket.closeTicket(12:00:00, 4.00) → marks ticket closed.
  17. Removes "T-00001" from activeTickets.
  18. Returns closed Ticket to Gate. Gate displays: "Total: $4.00. Thank you!"

10 Extensions & Edge Cases

EV Charging Slots
  • Add EV_CHARGING to the SlotType enum.
  • Create EVSlotStrategy implements SlotAllocationStrategy — prefers EV_CHARGING slots for electric cars, falls back to REGULAR if none available.
  • Zero changes to ParkingLot.java. Inject new EVSlotStrategy() at construction time.
Reservation / Pre-booking
  • Add SlotState enum: FREE, OCCUPIED, RESERVED. Replace AtomicBoolean with AtomicReference<SlotState>.
  • Add Reservation class: reservationId, vehicle, slot, startTime, endTime.
  • ParkingLot.reserve(vehicle, duration) transitions slot to RESERVED and returns a Reservation.
  • On arrival, park(vehicle, reservationId) uses the pre-assigned slot directly.
Monthly / Season Passes
  • Add PassHolder class: passId, vehicleId, validFrom, validUntil, passType.
  • In unpark(), check passRegistry.hasValidPass(vehicle) before calling pricingStrategy.calculateFee(). If valid, fee = 0.

  • Add Currency parameter to PricingStrategy: Money calculateFee(Ticket ticket, Currency currency).

OCP in every extension: Every one of these additions creates a new class or extends an interface. The core ParkingLot, ParkingSlot, and Vehicle classes remain untouched. This is Open/Closed Principle demonstrated in practice — the answer interviewers love to hear.

11 Interview Talking Points

Five Lines That Show Senior Depth
1. On Concurrency "I use AtomicBoolean.compareAndSet(false, true) for slot occupation — it's a lock-free CAS operation that prevents double-booking without synchronized overhead. I additionally wrap findSlot and occupy in a ReentrantLock to close the TOCTOU window between checking availability and claiming the slot."
2. On OCP / Strategy "Strategy Pattern on SlotAllocation means adding EV parking is a new class, not a rewrite. I pass the new strategy to ParkingLot's constructor — every caller is unaware. That's Open/Closed: the lot is open for new behaviors, closed to modification."
3. On Singleton "My Singleton uses double-checked locking with a volatile field. The volatile is critical — without it, the JVM's memory model allows partial initialization to be observed by a second thread, which would return a half-built ParkingLot and cause silent corruption."
4. On LSP "Vehicle hierarchy follows the Liskov Substitution Principle — Car, Bike, Truck are all Vehicles and pass through every method that accepts a Vehicle identically. No code downcasts to Car to do something special; VehicleType drives behavior through strategy dispatch, not instanceof."
5. On Extensibility Under Pressure "If the interviewer says 'trucks can now park across 2 consecutive slots', I add MultiSlotAllocationStrategy implements SlotAllocationStrategy that finds two adjacent LARGE slots and occupies both. ParkingLot.park() never changes — it still just calls strategy.findSlot(). The change is fully encapsulated in the new strategy class."
Bonus point getter: Mention that ConcurrentHashMap for activeTickets is intentional — multiple exit gates query and remove tickets concurrently, and CHM provides segment-level locking so they don't block each other on different ticket lookups.
