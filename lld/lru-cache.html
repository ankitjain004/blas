01 Requirements & Scope

Core API Contract

MethodBehaviourTime Complexity
get(key)Return value if found; -1 if absent. Mark key as most-recently-used.O(1)
put(key, value)Insert or update. If at capacity, evict the LRU entry first, then insert. Mark new key as MRU.O(1)

Constraints

  • Capacity is a fixed positive integer set at construction time.
  • Keys and values are generic types (not just int).
  • put on an existing key updates the value and promotes to MRU — no capacity change.

Clarifying Questions — Ask These First

QuestionWhy It Matters

Max entry size limit?Weighted eviction (e.g., Caffeine's weigher) — significant complexity
Critical framing for the interview: This is a data structures problem wrapped in OOD. The interviewer wants you to build HashMap+DLL from scratch, not use LinkedHashMap. Acknowledge that LinkedHashMap solves this in 10 lines, then say: "I'll implement the underlying structure to demonstrate the O(1) mechanics."

02 Why HashMap + DLL

Structure Aloneget(key)Find LRUCombined verdict
HashMap onlyO(1) ✅O(n) — must scan all entries for LRU ❌Insufficient
DLL onlyO(n) — must traverse to find key ❌O(1) — tail is always LRU ✅Insufficient
HashMap + DLLO(1) via map lookup ✅O(1) via tail.prev ✅✅ Perfect fit

The Insight

  • HashMap: key → Node pointer. Gives us the node in O(1) — no list traversal.
  • DLL: Maintains insertion order by recency. O(1) node removal and insertion anywhere given a pointer.
  • Together: HashMap finds the node in O(1), DLL repositions it in O(1). Both operations are O(1) total.

ASCII: Structure at a Glance

HashMap:                          Doubly Linked List (head=MRU side, tail=LRU side):
┌──────────────────────┐          ┌───────┐    ┌───────┐    ┌───────┐    ┌───────┐
│ "alice"  →  ●────────┼─────────▶│ dummy │◀──▶│ alice │◀──▶│  bob  │◀──▶│ dummy │
│  "bob"   →  ●────────┼──────┐   │ head  │    │  25   │    │  30   │    │ tail  │
│ "carol"  →  ●────────┼───┐  │   └───────┘    └───────┘    └───────┘    └───────┘
└──────────────────────┘   │  │
                           │  └──────────── "bob"  is at position 2 from MRU
                           └─────────────── "carol" is tail.prev = LRU → evicted next

  head.next  =  MRU  (most recently used)
  tail.prev  =  LRU  (least recently used — evicted when capacity exceeded)

  On get("alice"):  removeNode(alice_node)  →  addToFront(alice_node)
  Result:    head ↔ alice ↔ bob ↔ carol ↔ tail   (alice now MRU)

03 Node Class

/**
 * Doubly-linked list node. Stores both key AND value.
 * Generic K, V for type safety — no raw types.
 */
public class Node<K, V> {
    K key;
    V value;
    Node<K, V> prev;
    Node<K, V> next;

    // Sentinel constructor (no key/value needed for dummy head/tail)
    Node() {}

    Node(K key, V value) {
        this.key   = key;
        this.value = value;
    }
}

Why Does the Node Store the Key?

Critical non-obvious insight: When we evict the LRU node (tail.prev), we must also remove it from the HashMap — otherwise the map grows unbounded and the evicted entry returns on get(). Without the key in the node, we'd have to scan the entire HashMap to find the entry — O(n). With key stored in the node, eviction is map.remove(node.key) — O(1). 
// Eviction with key in Node — O(1):
Node<K, V> lru = dll.removeTail();   // O(1) pointer operation
map.remove(lru.key);                  // O(1) HashMap remove — key is RIGHT HERE

// Without key in Node — O(n) disaster:
Node<K, V> lru = dll.removeTail();
// Now we must find which map entry points to this node...
for (Map.Entry<K, Node<K,V>> entry : map.entrySet()) {  // O(n) scan!
    if (entry.getValue() == lru) {
        map.remove(entry.getKey());
        break;
    }
}

The generic type parameters K and V provide compile-time type safety, eliminating the ClassCastException that plagues raw-type Object implementations.

04 DoublyLinkedList Class

Uses two sentinel (dummy) nodes — head and tail — to eliminate null checks in every operation. Every real node always has a non-null prev and next.

public class DoublyLinkedList<K, V> {

    private final Node<K, V> head; // sentinel — head.next = MRU real node
    private final Node<K, V> tail; // sentinel — tail.prev = LRU real node

    public DoublyLinkedList() {
        head = new Node<>();
        tail = new Node<>();
        head.next = tail;
        tail.prev = head;
    }

    /** Insert node immediately after head (MRU position). O(1). */
    public void addToFront(Node<K, V> node) {
        node.prev      = head;
        node.next      = head.next;
        head.next.prev = node;
        head.next      = node;
    }

    /** Unlink node from wherever it currently sits. O(1). */
    public void removeNode(Node<K, V> node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
        // Help GC — clear dangling pointers
        node.prev = null;
        node.next = null;
    }

    /**
     * Remove and return the LRU node (tail.prev).
     * Called when capacity exceeded.
     * Returns the node so caller can extract the key for map.remove().
     */
    public Node<K, V> removeTail() {
        if (head.next == tail) return null; // empty list
        Node<K, V> lru = tail.prev;
        removeNode(lru);
        return lru;
    }

    public boolean isEmpty() { return head.next == tail; }
}

addToFront: Before & After

Before addToFront(X):
  head ↔ A ↔ B ↔ tail

Step-by-step pointer updates:
  1. X.prev      = head          →  head ← X        B ↔ tail   (A still attached to head)
  2. X.next      = head.next(=A) →  head ← X → A ↔ B ↔ tail
  3. head.next.prev (= A.prev)   →  head ← X ↔ A ↔ B ↔ tail   (A now points back to X)
  4. head.next   = X             →  head ↔ X ↔ A ↔ B ↔ tail   ✅

After addToFront(X):
  head ↔ X ↔ A ↔ B ↔ tail

removeNode: Before & After

Before removeNode(A)  where list is:  head ↔ X ↔ A ↔ B ↔ tail

  1. A.prev.next = A.next  →  X.next = B   (X now skips A going forward)
  2. A.next.prev = A.prev  →  B.prev = X   (B now skips A going backward)

After removeNode(A):
  head ↔ X ↔ B ↔ tail       (A is detached, eligible for GC)
Sentinel benefit in practice: Without sentinels, addToFront must check if (head.next == null). removeNode must check if (node == firstRealNode) and if (node == lastRealNode). Sentinels make every case uniform — the same 4-line addToFront works whether the list has 0 or 1000 real nodes.

05 LRUCache Class

import java.util.HashMap;
import java.util.Map;

public class LRUCache<K, V> {

    private final int capacity;
    private final Map<K, Node<K, V>> map;
    private final DoublyLinkedList<K, V> dll;

    public LRUCache(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("Capacity must be positive");
        this.capacity = capacity;
        this.map      = new HashMap<>(capacity * 2); // pre-size to avoid rehashing
        this.dll      = new DoublyLinkedList<>();
    }

    /**
     * Return value for key, or -1 if absent.
     * Promotes the accessed node to MRU position.
     * Time: O(1)
     */
    public V get(K key) {
        if (!map.containsKey(key)) return null; // return -1 for int caches

        Node<K, V> node = map.get(key);
        // Promote to MRU
        dll.removeNode(node);
        dll.addToFront(node);
        return node.value;
    }

    /**
     * Insert or update key-value pair.
     * If key exists: update value in-place, promote to MRU.
     * If new key and at capacity: evict LRU first, then insert.
     * Time: O(1)
     */
    public void put(K key, V value) {
        if (map.containsKey(key)) {
            // Update existing — no capacity change
            Node<K, V> node = map.get(key);
            node.value = value;
            dll.removeNode(node);
            dll.addToFront(node);
        } else {
            // New entry — check capacity
            if (map.size() == capacity) {
                Node<K, V> evicted = dll.removeTail();
                if (evicted != null) {
                    map.remove(evicted.key); // CRITICAL: remove from map too
                    System.out.println("[LRUCache] Evicted key: " + evicted.key);
                }
            }
            Node<K, V> newNode = new Node<>(key, value);
            dll.addToFront(newNode);
            map.put(key, newNode);
        }
    }

    /** Convenience: check if key exists without updating recency */
    public boolean containsKey(K key) { return map.containsKey(key); }

    /** Current number of entries */
    public int size() { return map.size(); }

    public int getCapacity() { return capacity; }

    @Override
    public String toString() {
        StringBuilder sb = new StringBuilder("LRUCache[MRU→LRU]: ");
        Node<K, V> cur = dll.getHead().next;
        while (cur != dll.getTail()) {
            sb.append(cur.key).append(":").append(cur.value).append(" → ");
            cur = cur.next;
        }
        sb.append("(LRU end)");
        return sb.toString();
    }
}

Approach 1: Synchronized Wrapper

public class SynchronizedLRUCache<K, V> extends LRUCache<K, V> {

    public SynchronizedLRUCache(int capacity) { super(capacity); }

    @Override
    public synchronized V get(K key) { return super.get(key); }

    @Override
    public synchronized void put(K key, V value) { super.put(key, value); }
}

Approach 2: ReadWriteLock Version

import java.util.concurrent.locks.*;

public class RWLockLRUCache<K, V> extends LRUCache<K, V> {

    private final ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
    private final Lock readLock  = rwLock.readLock();
    private final Lock writeLock = rwLock.writeLock();

    public RWLockLRUCache(int capacity) { super(capacity); }

    /**
     * NOTE: get() uses writeLock, NOT readLock.
     * get() mutates the DLL (move-to-front), so it is NOT a read-only operation.
     */
    @Override
    public V get(K key) {
        writeLock.lock(); // ← writeLock, not readLock!
        try {
            return super.get(key);
        } finally {
            writeLock.unlock();
        }
    }

    @Override
    public void put(K key, V value) {
        writeLock.lock();
        try {
            super.put(key, value);
        } finally {
            writeLock.unlock();
        }
    }
}
The subtle trap most candidates miss: get() is NOT read-only — it moves the accessed node to the front of the DLL (mutation). If you use readLock for get(), two concurrent gets on different keys will simultaneously mutate the DLL, causing pointer corruption. Both get() and put() require the write lock. ReadWriteLock only helps if you separate "read value" from "update recency" into two distinct operations with eventual consistency.

Approach 3: Approximate LRU (Highest Throughput)

import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class ApproximateLRUCache<K, V> {
    // ConcurrentHashMap for lock-free reads
    private final ConcurrentHashMap<K, V> map;
    // Bounded queue tracks access order (approximate — not strictly LRU)
    private final ConcurrentLinkedDeque<K> accessOrder;
    private final int capacity;

    public ApproximateLRUCache(int capacity) {
        this.capacity    = capacity;
        this.map         = new ConcurrentHashMap<>(capacity * 2);
        this.accessOrder = new ConcurrentLinkedDeque<>();
    }

    public V get(K key) {
        V value = map.get(key);
        if (value != null) {
            // Record access — approximate recency (best-effort, not exact)
            accessOrder.remove(key); // O(n) — trade accuracy for concurrency
            accessOrder.addFirst(key);
        }
        return value;
    }

    public void put(K key, V value) {
        if (map.size() >= capacity && !map.containsKey(key)) {
            K lru = accessOrder.pollLast(); // approximate LRU
            if (lru != null) map.remove(lru);
        }
        map.put(key, value);
        accessOrder.remove(key);
        accessOrder.addFirst(key);
    }
}
// Note: Caffeine library uses a more sophisticated "Window TinyLFU" approach
// for near-optimal hit rates at high concurrency — reference it in interviews.

07 Common Mistakes

Mistake 1 — Not storing key in Node: You evict tail.prev but cannot remove it from the HashMap without an O(n) scan. Always store the key in the Node so eviction is map.remove(node.key) — O(1).
Mistake 2 — Using LinkedHashMap: LinkedHashMap(capacity, 0.75f, true) with removeEldestEntry override solves this in ~10 lines. The interviewer will follow up: "Now implement the underlying structure." Show them you understand why by building it from scratch.
Mistake 3 — Forgetting to update map on eviction: 
// WRONG — memory leak: map grows without bound
Node<K, V> evicted = dll.removeTail(); // removes from DLL
// map.remove(evicted.key) MISSING ← evicted key still in map!
// Next put of same key: map finds stale node, returns wrong value
Mistake 4 — No sentinel nodes: Without sentinels, addToFront() on an empty list throws NullPointerException (head.next.prev = node where head.next = null). Sentinels eliminate ALL null checks.
Mistake 5 — Thread-safety ignored: In concurrent use, two threads calling put() simultaneously can corrupt the HashMap (resize race) and the DLL (interleaved pointer updates). Both methods need the write lock.
Edge cases to test explicitly:
  • get() on empty cache → returns -1/null, no exception
  • put() when capacity=1: second put evicts first, map size stays 1
  • put(key, newValue) for existing key: value updates, no eviction, no capacity change
  • get(key) after that key was evicted → returns -1/null (not stale value)
  • Capacity=0: constructor throws IllegalArgumentException

08 Extending: TTL Support

Approach 1 — Lazy Expiry (simpler, no background thread)

public class NodeWithTTL<K, V> extends Node<K, V> {
    long expiryTimeMs; // System.currentTimeMillis() + ttlMs at insertion

    NodeWithTTL(K key, V value, long ttlMs) {
        super(key, value);
        this.expiryTimeMs = (ttlMs > 0) ? System.currentTimeMillis() + ttlMs : Long.MAX_VALUE;
    }

    boolean isExpired() { return System.currentTimeMillis() > expiryTimeMs; }
}

// Modified get() with lazy expiry check:
public V get(K key) {
    if (!map.containsKey(key)) return null;

    NodeWithTTL<K, V> node = (NodeWithTTL<K, V>) map.get(key);

    if (node.isExpired()) {
        // Lazy eviction: remove on access
        dll.removeNode(node);
        map.remove(key);
        System.out.println("[TTL] Key '" + key + "' expired and removed on access");
        return null;
    }

    dll.removeNode(node);
    dll.addToFront(node);
    return node.value;
}

Approach 2 — Background Cleaner Thread (proactive, immediate memory reclaim)

import java.util.concurrent.*;

public class TTLLRUCache<K, V> extends LRUCache<K, V> {

    private final ScheduledExecutorService cleaner = Executors.newSingleThreadScheduledExecutor(r -> {
        Thread t = new Thread(r, "lru-ttl-cleaner");
        t.setDaemon(true); // don't prevent JVM shutdown
        return t;
    });

    public TTLLRUCache(int capacity, long cleanupIntervalMs) {
        super(capacity);
        cleaner.scheduleAtFixedRate(this::removeExpiredEntries,
            cleanupIntervalMs, cleanupIntervalMs, TimeUnit.MILLISECONDS);
    }

    private void removeExpiredEntries() {
        long now = System.currentTimeMillis();
        // Snapshot keys to avoid ConcurrentModificationException
        new java.util.HashSet<>(getMap().keySet()).forEach(key -> {
            Node<K, V> node = getMap().get(key);
            if (node instanceof NodeWithTTL && ((NodeWithTTL<?,?>)node).isExpired()) {
                synchronized (this) {
                    getDll().removeNode(node);
                    getMap().remove(key);
                    System.out.println("[TTL Cleaner] Expired: " + key);
                }
            }
        });
    }

    public void shutdown() { cleaner.shutdown(); }
}

09 Extending: Eviction Policy as Strategy

Open/Closed Principle in action: Adding LFU requires zero changes to LRUCache core logic — only a new EvictionPolicy implementation.

EvictionPolicy Interface

public interface EvictionPolicy<K, V> {
    /** Called on every get() or put() that accesses an existing key */
    void recordAccess(Node<K, V> node);

    /** Return the node that should be evicted next */
    Node<K, V> getEvictionCandidate();

    /** Remove node from policy data structures (called after eviction) */
    void remove(Node<K, V> node);
}

LRUEvictionPolicy — DLL-based

public class LRUEvictionPolicy<K, V> implements EvictionPolicy<K, V> {
    private final DoublyLinkedList<K, V> dll = new DoublyLinkedList<>();

    @Override
    public void recordAccess(Node<K, V> node) {
        dll.removeNode(node);
        dll.addToFront(node); // MRU position
    }

    @Override
    public Node<K, V> getEvictionCandidate() {
        return dll.getTail().prev; // LRU = tail.prev
    }

    @Override
    public void remove(Node<K, V> node) { dll.removeNode(node); }
}

LFUEvictionPolicy — Frequency Map-based

import java.util.*;

public class LFUEvictionPolicy<K, V> implements EvictionPolicy<K, V> {
    private final Map<Node<K,V>, Integer> freq = new HashMap<>();

    @Override
    public void recordAccess(Node<K, V> node) {
        freq.merge(node, 1, Integer::sum); // increment frequency
    }

    @Override
    public Node<K, V> getEvictionCandidate() {
        return freq.entrySet().stream()
            .min(Map.Entry.comparingByValue())
            .map(Map.Entry::getKey)
            .orElse(null);
    }

    @Override
    public void remove(Node<K, V> node) { freq.remove(node); }
}

RandomEvictionPolicy

public class RandomEvictionPolicy<K, V> implements EvictionPolicy<K, V> {
    private final List<Node<K, V>> nodes = new ArrayList<>();
    private final Random rng = new Random();

    @Override public void recordAccess(Node<K, V> node) { /* no-op */ }

    @Override public Node<K, V> getEvictionCandidate() {
        if (nodes.isEmpty()) return null;
        return nodes.get(rng.nextInt(nodes.size()));
    }

    @Override public void remove(Node<K, V> node) { nodes.remove(node); }
    public void add(Node<K, V> node) { nodes.add(node); }
}

LRUCache with Pluggable Policy

public class PolicyDrivenCache<K, V> {
    private final int capacity;
    private final Map<K, Node<K, V>> map;
    private final EvictionPolicy<K, V> policy;

    public PolicyDrivenCache(int capacity, EvictionPolicy<K, V> policy) {
        this.capacity = capacity;
        this.map      = new HashMap<>(capacity * 2);
        this.policy   = policy;
    }

    public V get(K key) {
        if (!map.containsKey(key)) return null;
        Node<K, V> node = map.get(key);
        policy.recordAccess(node); // delegate recency/frequency tracking
        return node.value;
    }

    public void put(K key, V value) {
        if (map.containsKey(key)) {
            Node<K, V> node = map.get(key);
            node.value = value;
            policy.recordAccess(node);
        } else {
            if (map.size() == capacity) {
                Node<K, V> victim = policy.getEvictionCandidate();
                if (victim != null) {
                    policy.remove(victim);
                    map.remove(victim.key);
                }
            }
            Node<K, V> newNode = new Node<>(key, value);
            policy.recordAccess(newNode);
            map.put(key, newNode);
        }
    }
}

10 Walking a Flow (capacity = 3)

Initial state: empty cache
  DLL:  [head] ↔ [tail]
  Map:  {}

──────────────────────────────────────────────────────────────────────────────
Step 1: put(1, "A")
  New node. map.size()=0 < capacity=3. No eviction needed.
  Create node1(key=1, val="A"). addToFront(node1). map.put(1, node1).
  DLL:  [head] ↔ [1:A] ↔ [tail]
  Map:  {1→node1}

──────────────────────────────────────────────────────────────────────────────
Step 2: put(2, "B")
  New node. map.size()=1 < 3. No eviction.
  DLL:  [head] ↔ [2:B] ↔ [1:A] ↔ [tail]
  Map:  {1→node1, 2→node2}

──────────────────────────────────────────────────────────────────────────────
Step 3: put(3, "C")
  New node. map.size()=2 < 3. No eviction.
  DLL:  [head] ↔ [3:C] ↔ [2:B] ↔ [1:A] ↔ [tail]
  Map:  {1,2,3}
  LRU = tail.prev = node1 (key=1)

──────────────────────────────────────────────────────────────────────────────
Step 4: get(1)   ← access key 1 (currently LRU)
  map.get(1) = node1. Found!
  removeNode(node1) → DLL: [head] ↔ [3:C] ↔ [2:B] ↔ [tail]
  addToFront(node1) → DLL: [head] ↔ [1:A] ↔ [3:C] ↔ [2:B] ↔ [tail]
  Return "A".
  Map:  {1,2,3}  ← unchanged
  LRU = tail.prev = node2 (key=2) ← key 2 is now LRU

──────────────────────────────────────────────────────────────────────────────
Step 5: put(4, "D")   ← cache FULL, eviction required
  map.size()=3 == capacity=3. Evict LRU.
  dll.removeTail() → removes node2 (key=2, val="B")
  map.remove(2)    → Map: {1,3}
  Create node4. addToFront(node4).
  DLL:  [head] ↔ [4:D] ↔ [1:A] ↔ [3:C] ↔ [tail]
  Map:  {1→node1, 3→node3, 4→node4}
  LRU = tail.prev = node3 (key=3)

──────────────────────────────────────────────────────────────────────────────
Step 6: get(2)   ← key 2 was evicted in Step 5
  map.containsKey(2) → false
  Return null / -1   ✅ correctly reports miss

──────────────────────────────────────────────────────────────────────────────
Final state:
  DLL:  [head] ↔ [4:D] ↔ [1:A] ↔ [3:C] ↔ [tail]
  Map:  {1:"A", 3:"C", 4:"D"}
  MRU = key 4,  LRU = key 3

11 Interview Talking Points

1. Building DLL+HashMap manually "I implement the DLL and HashMap from scratch rather than using LinkedHashMap. This demonstrates I understand why O(1) is achievable — the HashMap gives O(1) pointer lookup, the DLL gives O(1) pointer manipulation. LinkedHashMap does exactly this internally, and I can explain every line of how it works." 2. Sentinel nodes eliminate null checks "Without sentinels, addToFront on an empty list requires a null guard. removeNode for the first or last element requires special cases. Sentinels make every case structurally identical — the same 4-line addToFront works for a list of 1 or 10,000 elements." 3. Key in Node — the non-obvious insight "When evicting tail.prev, I need to call map.remove(). Without the key stored in the node, I'd have to scan the entire HashMap to find which entry points to this node — O(n). Storing key in Node makes it map.remove(node.key) — O(1). This is the most commonly missed detail." 4. get() mutates DLL — no read locks "This is the subtle concurrency gotcha: get() isn't read-only. It moves the accessed node to front — a DLL mutation. If I use ReadWriteLock and put get() behind a read lock, two concurrent gets will race on DLL pointer updates and corrupt the list. Both get() and put() need the write lock." 5. TTL as zero-impact extension "Adding TTL requires only adding an expiryTime field to Node and a check at the top of get(). The core put() logic, the DLL, and the HashMap are completely unchanged.
