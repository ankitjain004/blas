01Group Anagrams Medium

Section · String
LeetCode
Problem

Given a list of words, cluster together the ones that are anagrams of each other (same letters, any order). Return the groups in any order.

Example

Input: ["eat","tea","tan","ate","nat","bat"]  ·  Output: [["eat","tea","ate"],["tan","nat"],["bat"]]

  1. Sort each word: eat→aet, tea→aet, ate→aet share a key.
  2. tan→ant, nat→ant share a key; bat→abt is alone.
  3. Collect the map's values as the answer.
Mental Model
A canonical signature is the group id. Any two anagrams reduce to the same sorted string (or the same 26-letter count vector), so bucket words by that signature in a hash map.
Other Approaches
Brute Compare every pair for anagram-ness — O(n² · k).
Better Sorted-string key in a hash map — O(n · k log k).
Optimal Approach
  1. For each word, build a 26-length count array and turn it into a string key.
  2. Append the word to the map bucket for that key.
  3. Return all buckets — key build is O(k), so total is O(n·k).
Visual
flowchart LR
  W["word"] --> K["count signature"]
  K --> M{"key seen?"}
  M -- yes --> A["append to bucket"]
  M -- no --> N["new bucket"]
Code (Java)
List<List<String>> groupAnagrams(String[] strs){
  Map<String, List<String>> groups = new HashMap<>();
  for(String s : strs){
    int[] count = new int[26];
    for(int i = 0; i < s.length(); i++) count[s.charAt(i) - 'a']++;

    StringBuilder key = new StringBuilder();
    for(int c : count){ key.append('#'); key.append(c); }

    groups.computeIfAbsent(key.toString(), k -> new ArrayList<>()).add(s);
  }
  return new ArrayList<>(groups.values());
}
Time O(n · k)
Space O(n · k)

02Minimum Window Substring Hard

Section · String
LeetCode
Problem

Given strings s and t, find the shortest contiguous slice of s that contains every character of t (counting duplicates). Return the empty string if none exists.

Example

Input: s = "ADOBECODEBANC", t = "ABC"  ·  Output: "BANC"

  1. Expand right until the window covers A, B, C — first hit is "ADOBEC".
  2. Shrink from the left while still valid, recording the smallest.
  3. Continue sliding; the final tightest valid window is "BANC".
Mental Model
Grow to become valid, shrink to stay minimal. A have == need counter tells you when all required characters are present so you can contract the left edge without a full recount.
Other Approaches
Brute Check every substring for coverage — O(n² · m).
Better Two-pointer window with a frequency map — O(n + m).
Optimal Approach
  1. Count needed chars; track how many distinct requirements are satisfied.
  2. Move right, decrementing the need; when a char's need hits zero, bump have.
  3. While have == need, record window if smaller, then advance left.
Visual
flowchart LR
  R["move right"] --> V{"window valid?"}
  V -- no --> R
  V -- yes --> S["record best; move left"]
  S --> V
Code (Java)
String minWindow(String s, String t){
  if(s.length() < t.length()) return "";

  int[] need = new int[128];
  for(char c : t.toCharArray()) need[c]++;
  int required = t.length();

  int left = 0, bestLen = Integer.MAX_VALUE, bestStart = 0;
  for(int right = 0; right < s.length(); right++){
    if(need[s.charAt(right)]-- > 0) required--;          // consumed a needed char

    while(required == 0){                                 // window covers all of t
      if(right - left + 1 < bestLen){
        bestLen = right - left + 1;
        bestStart = left;
      }
      if(need[s.charAt(left)]++ == 0) required++;         // giving back a needed char
      left++;
    }
  }
  return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
}
Time O(n + m)
Space O(1)

03Longest Repeating Character Replacement Medium

Section · String Part-II
LeetCode
Problem

Given a string of uppercase letters and a budget k, you may replace up to k characters with any letters. Return the length of the longest run you can make identical.

Example

Input: s = "AABABBA", k = 1  ·  Output: 4

  1. Window "AABA" has 3 A's; one replacement fixes the B → length 4.
  2. Extending further needs 2 replacements, exceeding k.
  3. Best achievable window length is 4.
Mental Model
A window is valid when (length − maxFreq) ≤ k. That leftover count is exactly the number of characters you'd have to overwrite; keep the window as wide as this rule allows.
Other Approaches
Brute Try every substring and count replacements — O(n²).
Better Sliding window tracking the most frequent letter — O(n).
Optimal Approach
  1. Expand right, updating the frequency of the incoming char and maxFreq.
  2. If windowLen − maxFreq > k, slide left once to shrink.
  3. The answer is the maximum window width ever reached.
Visual
flowchart LR
  E["expand right"] --> C{"len minus maxFreq over k?"}
  C -- yes --> L["move left once"]
  C -- no --> U["update best length"]
  L --> U
Code (Java)
int characterReplacement(String s, int k){
  int[] freq = new int[26];
  int left = 0, maxFreq = 0, best = 0;

  for(int right = 0; right < s.length(); right++){
    int idx = s.charAt(right) - 'A';
    freq[idx]++;
    maxFreq = Math.max(maxFreq, freq[idx]);

    while((right - left + 1) - maxFreq > k){              // too many chars to replace
      freq[s.charAt(left) - 'A']--;
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}
Time O(n)
Space O(1)

04String Compression Medium

Section · String Part-II
LeetCode
Problem

Compress a character array in place: each run of a repeated char becomes the char followed by its count (counts > 1 only). Return the new length; the first that-many slots must hold the compressed form.

Example

Input: ['a','a','b','b','c','c','c']  ·  Output: 6, array starts ['a','2','b','2','c','3']

  1. Run of 2 a's → write a2.
  2. Run of 2 b's → write b2.
  3. Run of 3 c's → write c3; total written is 6.
Mental Model
Read pointer scans runs; write pointer lays down results. Because compressed output never overtakes the read cursor, you can overwrite the same array safely in one pass.
Other Approaches
Brute Build a separate StringBuilder then copy back — O(n) time but O(n) space.
Better Two-pointer in-place write — O(1) extra space.
Optimal Approach
  1. Let read find the end of each equal run; compute its length.
  2. Write the char, then each digit of the count when the length exceeds 1.
  3. Return the final write index as the compressed length.
Visual
flowchart LR
  R["read a run"] --> C["count length"]
  C --> W["write char"]
  W --> D{"count over 1?"}
  D -- yes --> N["write digits"]
  D -- no --> R
Code (Java)
int compress(char[] chars){
  int write = 0, read = 0, n = chars.length;

  while(read < n){
    char cur = chars[read];
    int count = 0;
    while(read < n && chars[read] == cur){                 // measure the run
      read++;
      count++;
    }
    chars[write++] = cur;
    if(count > 1){
      for(char digit : String.valueOf(count).toCharArray())
        chars[write++] = digit;
    }
  }
  return write;
}
Time O(n)
Space O(1)

05Right View of Binary Tree Medium

Section · Binary Tree
LeetCode
Problem

Standing to the right of a binary tree, return the values you can see top to bottom — that is, the last node encountered on each level.

Example

Input: [1,2,3,null,5,null,4]  ·  Output: [1,3,4]

  1. Level 0: only node 1 is visible.
  2. Level 1: rightmost is 3.
  3. Level 2: rightmost is 4.
Mental Model
Level-order, keep the last per level. A BFS that processes each level as a batch lets you grab the final node of the batch as the right-side view.
Other Approaches
Brute Compute full level order, then take last of each level — O(n) with extra lists.
Better DFS visiting right child first, record first node per depth — O(n).
Optimal Approach
  1. BFS with a queue; for each level, note its size.
  2. Iterate that many nodes; when you reach the last, add its value.
  3. Push children left-to-right so the last dequeued is the rightmost.
Visual
flowchart TD
  Q["queue level"] --> L["process size nodes"]
  L --> E{"last in level?"}
  E -- yes --> A["add to view"]
  E -- no --> L
Code (Java)
List<Integer> rightSideView(TreeNode root){
  List<Integer> view = new ArrayList<>();
  if(root == null) return view;

  Queue<TreeNode> queue = new LinkedList<>();
  queue.offer(root);
  while(!queue.isEmpty()){
    int size = queue.size();
    for(int i = 0; i < size; i++){
      TreeNode node = queue.poll();
      if(i == size - 1) view.add(node.val);             // last node of this level
      if(node.left != null)  queue.offer(node.left);
      if(node.right != null) queue.offer(node.right);
    }
  }
  return view;
}
Time O(n)
Space O(w)

06Symmetric Tree Easy

Section · Binary Tree
LeetCode
Problem

Decide whether a binary tree is a mirror image of itself around the center — the left subtree reflected equals the right subtree.

Example

Input: [1,2,2,3,4,4,3]  ·  Output: true

  1. Compare left.left with right.right → 3 vs 3.
  2. Compare left.right with right.left → 4 vs 4.
  3. All mirrored pairs match, so the tree is symmetric.
Mental Model
Mirror check on two pointers. Two subtrees mirror if their roots match and, crucially, the outer child of one lines up with the outer child of the other (left.left vs right.right).
Other Approaches
Brute Serialize the tree and compare with its reversed form — awkward with nulls.
Better Iterative BFS pushing mirror pairs into a queue — O(n).
Optimal Approach
  1. Recurse on a pair (a, b); both null → symmetric, one null → not.
  2. Values must be equal to continue.
  3. Recurse on (a.left, b.right) and (a.right, b.left).
Visual
flowchart TD
  P["compare a and b"] --> V{"values equal?"}
  V -- no --> F["not symmetric"]
  V -- yes --> O["check a.left vs b.right"]
  O --> I["check a.right vs b.left"]
Code (Java)
boolean isSymmetric(TreeNode root){
  return root == null || isMirror(root.left, root.right);
}

private boolean isMirror(TreeNode a, TreeNode b){
  if(a == null && b == null) return true;
  if(a == null || b == null) return false;
  if(a.val != b.val) return false;
  return isMirror(a.left, b.right) && isMirror(a.right, b.left);
}
Time O(n)
Space O(h)

07Lowest Common Ancestor of a Binary Tree Medium

Section · Binary Tree Part-II
LeetCode
Problem

Given two nodes p and q in a binary tree (no BST ordering, no parent links), find their lowest common ancestor — the deepest node that has both in its subtree.

Example

Input: root = [3,5,1,6,2,0,8], p = 5, q = 1  ·  Output: 3

  1. 5 lives in the left subtree of 3; 1 lives in the right subtree.
  2. The split happens at node 3.
  3. So 3 is the lowest common ancestor.
Mental Model
Post-order returns "who did I find below me." If a node sees p on one side and q on the other, it is the LCA; otherwise it bubbles up whichever it found.
Other Approaches
Brute Record root-to-node paths for both, compare — O(n) time and space.
Better Parent map + set of ancestors — O(n) but two passes.
Optimal Approach
  1. Recurse; if the node is null or equals p/q, return it.
  2. Collect results from left and right subtrees.
  3. If both are non-null, this node is the LCA; else return the non-null one.
Visual
flowchart TD
  N["node"] --> B{"both sides found?"}
  B -- yes --> A["node is LCA"]
  B -- no --> U["return found side"]
Code (Java)
TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q){
  if(root == null || root == p || root == q) return root;

  TreeNode left  = lowestCommonAncestor(root.left,  p, q);
  TreeNode right = lowestCommonAncestor(root.right, p, q);

  if(left != null && right != null) return root;         // p and q split here
  return left != null ? left : right;                    // both on one side (or none)
}
Time O(n)
Space O(h)

08Path Sum II Medium

Section · Binary Tree Part-II
LeetCode
Problem

Return every root-to-leaf path whose node values add up to a given target sum. Each path is the ordered list of values from the root down to a leaf.

Example

Input: root = [5,4,8,11,null,13,4,7,2,null,null,5,1], target = 22  ·  Output: [[5,4,11,2],[5,8,4,5]]

  1. Path 5→4→11→2 sums to 22 at a leaf.
  2. Path 5→8→4→5 also sums to 22 at a leaf.
  3. Both complete paths are collected.
Mental Model
DFS with backtracking. Push the node onto the current path and subtract from the remaining target; at a leaf check for zero; always pop the node on the way out to restore state.
Other Approaches
Brute Enumerate all root-to-leaf paths, then filter by sum — same cost, messier.
Better Single DFS carrying the running remainder — O(n) visits.
Optimal Approach
  1. DFS carrying the current path list and remaining sum.
  2. At a leaf, if remaining equals the node value, snapshot the path.
  3. Recurse into children, then backtrack by removing the last node.
Visual
flowchart TD
  N["add node; subtract value"] --> L{"leaf and sum zero?"}
  L -- yes --> S["save path copy"]
  L -- no --> R["recurse children"]
  R --> B["remove node; backtrack"]
Code (Java)
List<List<Integer>> pathSum(TreeNode root, int target){
  List<List<Integer>> result = new ArrayList<>();
  dfs(root, target, new ArrayList<>(), result);
  return result;
}

private void dfs(TreeNode node, int remain, List<Integer> path, List<List<Integer>> result){
  if(node == null) return;

  path.add(node.val);
  if(node.left == null && node.right == null && remain == node.val){
    result.add(new ArrayList<>(path));                   // leaf that hits the target
  } else {
    dfs(node.left,  remain - node.val, path, result);
    dfs(node.right, remain - node.val, path, result);
  }
  path.remove(path.size() - 1);                          // backtrack
}
Time O(n²)
Space O(h)

09Flatten Binary Tree to Linked List Medium

Section · Binary Tree Part-III
LeetCode
Problem

Rearrange a binary tree in place into a "linked list" that follows pre-order: every node's left child becomes null and its right child points to the next pre-order node.

Example

Input: [1,2,5,3,4,null,6]  ·  Output: [1,null,2,null,3,null,4,null,5,null,6]

  1. Pre-order is 1,2,3,4,5,6.
  2. Each node keeps only a right pointer to the next.
  3. All left pointers become null.
Mental Model
Rewire using the predecessor. For each node with a left child, splice the whole left subtree between the node and its right subtree by attaching the right subtree to the left subtree's rightmost node.
Other Approaches
Brute Collect pre-order into a list, then relink — O(n) time and space.
Better Reverse pre-order recursion with a running prev — O(h) stack.
Optimal Approach
  1. Walk with cur; whenever it has a left child, find that subtree's rightmost node.
  2. Attach cur.right under that rightmost node, move left subtree to the right.
  3. Null out cur.left and advance cur — pure O(1) space.
Visual
flowchart LR
  C["cur has left?"] --> F["find left's rightmost"]
  F --> A["attach cur.right there"]
  A --> M["move left to right; left null"]
  M --> N["cur = cur.right"]
Code (Java)
void flatten(TreeNode root){
  TreeNode cur = root;
  while(cur != null){
    if(cur.left != null){
      TreeNode rightmost = cur.left;
      while(rightmost.right != null) rightmost = rightmost.right;

      rightmost.right = cur.right;                        // splice right subtree after left
      cur.right = cur.left;
      cur.left = null;
    }
    cur = cur.right;
  }
}
Time O(n)
Space O(1)

10Count Complete Tree Nodes Easy

Section · Binary Tree Part-III
LeetCode
Problem

Count the nodes of a complete binary tree (every level full except possibly the last, which fills left to right) in better than linear time.

Example

Input: [1,2,3,4,5,6]  ·  Output: 6

  1. Left height from root is 3; right height is 3.
  2. Unequal for a subtree means recurse; here the last level is partial.
  3. Summing full subtrees plus recursion yields 6.
Mental Model
Left-spine and right-spine heights collapse the work. If they match, the subtree is perfect and holds 2^h − 1 nodes instantly; otherwise recurse — only one side is ever imperfect.
Other Approaches
Brute Plain traversal counting every node — O(n).
Better Height-comparison recursion — O(log² n).
Optimal Approach
  1. Measure leftmost depth and rightmost depth.
  2. If equal, return 2^depth − 1 without recursing.
  3. Otherwise return 1 + count(left) + count(right).
Visual
flowchart TD
  H["measure left and right height"] --> E{"heights equal?"}
  E -- yes --> P["return 2^h minus 1"]
  E -- no --> R["1 plus recurse both sides"]
Code (Java)
int countNodes(TreeNode root){
  if(root == null) return 0;

  int leftH = leftHeight(root);
  int rightH = rightHeight(root);
  if(leftH == rightH) return (1 << leftH) - 1;            // perfect subtree

  return 1 + countNodes(root.left) + countNodes(root.right);
}

private int leftHeight(TreeNode node){
  int h = 0;
  while(node != null){ h++; node = node.left; }
  return h;
}

private int rightHeight(TreeNode node){
  int h = 0;
  while(node != null){ h++; node = node.right; }
  return h;
}
Time O(log² n)
Space O(log n)

11Recover Binary Search Tree Medium

Section · Binary Search Tree
LeetCode
Problem

Exactly two nodes of a BST were swapped by mistake. Restore the tree by putting their values back, without changing the tree's structure.

Example

Input: [3,1,4,null,null,2]  ·  Output: [2,1,4,null,null,3]

  1. In-order should be increasing: here it reads 1,3,2,4.
  2. Two dips: 3>2 flags 3 (first) and 2 (second).
  3. Swap 3 and 2 to fix the tree.
Mental Model
In-order of a valid BST is strictly increasing. The two swapped nodes create one or two descents; the first offender is the earlier dip's high value, the second is the later dip's low value.
Other Approaches
Brute Copy in-order to an array, sort, find mismatches — O(n) space.
Better In-order traversal tracking prev — O(h) space.
Optimal Approach
  1. Traverse in-order keeping the previous node.
  2. On each descent (prev.val > cur.val), record first = prev once and always second = cur.
  3. After traversal, swap the values of first and second.
Visual
flowchart LR
  I["inorder walk"] --> D{"prev over cur?"}
  D -- yes --> M["mark first and second"]
  D -- no --> I
  M --> S["swap values"]
Code (Java)
private TreeNode first, second, prev;

void recoverTree(TreeNode root){
  inorder(root);
  int tmp = first.val;                                    // swap the two offenders back
  first.val = second.val;
  second.val = tmp;
}

private void inorder(TreeNode node){
  if(node == null) return;
  inorder(node.left);
  if(prev != null && prev.val > node.val){
    if(first == null) first = prev;                       // earlier dip's high value
    second = node;                                        // later dip's low value
  }
  prev = node;
  inorder(node.right);
}
Time O(n)
Space O(h)

12Convert Sorted List to BST Medium

Section · Binary Search Tree
LeetCode
Problem

Turn a singly linked list sorted in ascending order into a height-balanced binary search tree.

Example

Input: [-10,-3,0,5,9]  ·  Output: a balanced BST rooted at 0

  1. Middle element 0 becomes the root.
  2. Left half [-10,-3] builds the left subtree.
  3. Right half [5,9] builds the right subtree.
Mental Model
The middle is always the root. Using in-order simulation, build left subtree first, consume the current list node as the root, then build the right — this maps a sorted sequence to a balanced BST in linear time.
Other Approaches
Brute Copy to an array, then index the middle recursively — O(n) space.
Better Slow/fast pointer to find middle each recursion — O(n log n).
Optimal Approach
  1. Count the list length once.
  2. Recurse over an index range; build left subtree, then take the current head as the node.
  3. Advance the shared head pointer and build the right subtree — in-order alignment.
Visual
flowchart TD
  R["range lo..hi"] --> L["build left half"]
  L --> M["take head as root"]
  M --> A["advance head"]
  A --> RR["build right half"]
Code (Java)
private ListNode head;

TreeNode sortedListToBST(ListNode node){
  int n = 0;
  for(ListNode p = node; p != null; p = p.next) n++;
  head = node;
  return build(0, n - 1);
}

private TreeNode build(int lo, int hi){
  if(lo > hi) return null;
  int mid = (lo + hi) / 2;

  TreeNode left = build(lo, mid - 1);                     // build left first (in-order)
  TreeNode root = new TreeNode(head.val);
  root.left = left;
  head = head.next;                                       // consume middle
  root.right = build(mid + 1, hi);
  return root;
}
Time O(n)
Space O(log n)

13Range Sum of BST Easy

Section · Binary Search Tree Part-II
LeetCode
Problem

Given the root of a BST and an inclusive range [low, high], add up the values of every node whose value lies within that range.

Example

Input: root = [10,5,15,3,7,null,18], low = 7, high = 15  ·  Output: 32

  1. Nodes in range: 10, 7, 15.
  2. 3 is below low; 18 is above high — both pruned.
  3. Sum is 10 + 7 + 15 = 32.
Mental Model
Use BST ordering to prune whole subtrees. If a node is below low, skip its left; if above high, skip its right — you never visit branches that cannot contribute.
Other Approaches
Brute Visit every node, add those in range — O(n) ignoring order.
Better Pruned DFS honoring BST bounds — visits only relevant nodes.
Optimal Approach
  1. If node is null, contribute 0.
  2. If val < low, recurse right only; if val > high, recurse left only.
  3. Otherwise add val and recurse both sides.
Visual
flowchart TD
  N["node"] --> B{"val below low?"}
  B -- yes --> R["go right only"]
  B -- no --> H{"val above high?"}
  H -- yes --> L["go left only"]
  H -- no --> A["add val; go both"]
Code (Java)
int rangeSumBST(TreeNode root, int low, int high){
  if(root == null) return 0;
  if(root.val < low)  return rangeSumBST(root.right, low, high);
  if(root.val > high) return rangeSumBST(root.left,  low, high);

  return root.val
       + rangeSumBST(root.left,  low, high)
       + rangeSumBST(root.right, low, high);
}
Time O(n)
Space O(h)

14Trim a Binary Search Tree Medium

Section · Binary Search Tree Part-II
LeetCode
Problem

Given a BST and bounds [low, high], remove all nodes whose values fall outside the range so that every remaining value is within bounds, while preserving the BST's relative structure.

Example

Input: root = [3,0,4,null,2,null,null,1], low = 1, high = 3  ·  Output: [3,2,null,1]

  1. 0 is below low → drop it, keep its right subtree.
  2. 4 is above high → drop it, keep its left subtree.
  3. Result keeps 1, 2, 3 in valid BST shape.
Mental Model
Return the trimmed subtree upward. When a node is out of range, it hands back the one side that could still hold in-range values; when in range, it trims both children and returns itself.
Other Approaches
Brute Collect valid values and rebuild a BST — loses original shape, more work.
Better Single recursive trim reusing existing nodes — O(n).
Optimal Approach
  1. Null node returns null.
  2. If val < low, return trimmed right subtree; if val > high, return trimmed left subtree.
  3. Otherwise trim both children in place and return the node.
Visual
flowchart TD
  N["node"] --> B{"val below low?"}
  B -- yes --> R["return trim right"]
  B -- no --> H{"val above high?"}
  H -- yes --> L["return trim left"]
  H -- no --> K["trim both; keep node"]
Code (Java)
TreeNode trimBST(TreeNode root, int low, int high){
  if(root == null) return null;

  if(root.val < low)  return trimBST(root.right, low, high);
  if(root.val > high) return trimBST(root.left,  low, high);

  root.left  = trimBST(root.left,  low, high);
  root.right = trimBST(root.right, low, high);
  return root;
}
Time O(n)
Space O(h)

Problem

A node is "good" if no node on the path from the root to it has a strictly greater value. Count how many good nodes the tree contains.

Example

Input: [3,1,4,3,null,1,5]  ·  Output: 4

  1. Root 3 is always good.
  2. 4, then 5 on its path, and the deeper 3 are good.
  3. The 1's are dominated by 3, so they are not good.
Mental Model
Carry the max-so-far down the path. A node is good exactly when its value is at least the largest value seen from the root; update that running max as you descend.

Brute For each node recompute its root path max — O(n²).

  1. DFS carrying maxSoFar, starting at the root value.
  2. Count the node if val >= maxSoFar; update the max for children.

int goodNodes(TreeNode root){

private int dfs(TreeNode node, int maxSoFar){

16All Nodes Distance K in Binary Tree Medium

Section · Binary Trees (Misc)
LeetCode
Problem

Given a binary tree, a target node, and an integer k, return the values of all nodes exactly k edges away from the target, in any order.

Example

Input: root = [3,5,1,6,2,0,8,null,null,7,4], target = 5, k = 2  ·  Output: [7,4,1]

  1. From 5, distance 2 downward reaches 7 and 4.
  2. Going up to 3 then down to 1 is also distance 2.
  3. Answer set is {7, 4, 1}.
Mental Model
Add parent links, then BFS from the target. Once each node knows its parent, the tree behaves like an undirected graph and a level-by-level BFS of depth k gives the answer.
Other Approaches
Brute For each node compute its distance to target via path search — O(n²).
Better DFS returning depth plus upward propagation — O(n) but trickier.
Optimal Approach
  1. Map every node to its parent with one DFS.
  2. BFS from target over left, right, and parent, marking visited.
  3. After k levels, the queue holds all distance-k nodes.
Visual
flowchart LR
  P["record parents"] --> Q["BFS from target"]
  Q --> N["visit left right parent"]
  N --> D{"reached depth k?"}
  D -- yes --> R["collect queue"]
  D -- no --> Q
Code (Java)
List<Integer> distanceK(TreeNode root, TreeNode target, int k){
  Map<TreeNode, TreeNode> parent = new HashMap<>();
  mapParents(root, null, parent);

  Queue<TreeNode> queue = new LinkedList<>();
  Set<TreeNode> seen = new HashSet<>();
  queue.offer(target);
  seen.add(target);

  int dist = 0;
  while(!queue.isEmpty()){
    if(dist == k){
      List<Integer> res = new ArrayList<>();
      for(TreeNode node : queue) res.add(node.val);
      return res;
    }
    int size = queue.size();
    for(int i = 0; i < size; i++){
      TreeNode node = queue.poll();
      for(TreeNode next : new TreeNode[]{ node.left, node.right, parent.get(node) }){
        if(next != null && seen.add(next)) queue.offer(next);
      }
    }
    dist++;
  }
  return new ArrayList<>();
}

private void mapParents(TreeNode node, TreeNode par, Map<TreeNode, TreeNode> parent){
  if(node == null) return;
  parent.put(node, par);
  mapParents(node.left,  node, parent);
  mapParents(node.right, node, parent);
}
Time O(n)
Space O(n)

17Course Schedule Medium

Section · Graph
LeetCode
Problem

You have numCourses courses and a list of prerequisite pairs [a, b] meaning b must come before a. Decide whether it is possible to finish all courses.

Example

Input: numCourses = 2, prerequisites = [[1,0]]  ·  Output: true

  1. Course 0 has no prerequisites → take it first.
  2. Course 1 depends only on 0 → take it next.
  3. No cycle exists, so all courses finish.
Mental Model
Feasible iff the dependency graph is acyclic. Kahn's algorithm repeatedly removes zero-indegree nodes; if you can remove all of them, there is no cycle.
Other Approaches
Brute Try permutations of course order — factorial blowup.
Better DFS cycle detection with a recursion-stack color — O(V + E).
Optimal Approach
  1. Build adjacency list and indegree counts.
  2. Queue all zero-indegree nodes; pop one, decrement neighbors, enqueue new zeros.
  3. If the number processed equals numCourses, return true.
Visual
flowchart LR
  I["compute indegrees"] --> Q["queue zero indegree"]
  Q --> P["pop; drop edges"]
  P --> N{"neighbor indegree zero?"}
  N -- yes --> Q
  P --> C["count processed"]
Code (Java)
boolean canFinish(int numCourses, int[][] prerequisites){
  List<List<Integer>> graph = new ArrayList<>();
  for(int i = 0; i < numCourses; i++) graph.add(new ArrayList<>());
  int[] indegree = new int[numCourses];

  for(int[] pre : prerequisites){
    graph.get(pre[1]).add(pre[0]);                        // pre[1] -> pre[0]
    indegree[pre[0]]++;
  }

  Queue<Integer> queue = new LinkedList<>();
  for(int i = 0; i < numCourses; i++) if(indegree[i] == 0) queue.offer(i);

  int done = 0;
  while(!queue.isEmpty()){
    int course = queue.poll();
    done++;
    for(int next : graph.get(course)){
      if(--indegree[next] == 0) queue.offer(next);
    }
  }
  return done == numCourses;
}
Time O(V + E)
Space O(V + E)

18Surrounded Regions Medium

Section · Graph
LeetCode
Problem

On a board of 'X' and 'O', flip every 'O' that is completely surrounded by 'X' to 'X'. Any 'O' connected to the border survives.

Example

Input: [["X","X","X"],["X","O","X"],["X","X","X"]]  ·  Output: the center O flipped to X

  1. The lone O is not connected to any border.
  2. So it is fully surrounded.
  3. It flips to X.
Mental Model
Solve the complement: mark the survivors first. Flood-fill from every border 'O' to protect connected regions, then flip all remaining interior 'O's.
Other Approaches
Brute For each O, search whether it can reach the border — O((mn)²).
Better Union-Find binding border O's to a virtual node — O(mn·α).
Optimal Approach
  1. DFS from each border 'O', temporarily marking safe cells as '#'.
  2. Scan the whole board: turn 'O' into 'X' (surrounded).
  3. Turn every '#' back to 'O' (was border-connected).
Visual
flowchart LR
  B["flood fill border O"] --> M["mark safe as hash"]
  M --> S["scan board"]
  S --> F["O to X; hash to O"]
Code (Java)
void solve(char[][] board){
  if(board.length == 0) return;
  int m = board.length, n = board[0].length;

  for(int i = 0; i < m; i++){
    mark(board, i, 0, m, n);
    mark(board, i, n - 1, m, n);
  }
  for(int j = 0; j < n; j++){
    mark(board, 0, j, m, n);
    mark(board, m - 1, j, m, n);
  }

  for(int i = 0; i < m; i++){
    for(int j = 0; j < n; j++){
      if(board[i][j] == 'O') board[i][j] = 'X';           // truly surrounded
      else if(board[i][j] == '#') board[i][j] = 'O';      // border-connected
    }
  }
}

private void mark(char[][] board, int i, int j, int m, int n){
  if(i < 0 || j < 0 || i >= m || j >= n || board[i][j] != 'O') return;
  board[i][j] = '#';
  mark(board, i + 1, j, m, n);
  mark(board, i - 1, j, m, n);
  mark(board, i, j + 1, m, n);
  mark(board, i, j - 1, m, n);
}
Time O(m · n)
Space O(m · n)

19Number of Provinces (Union-Find) Medium

Section · Graph Part-II
LeetCode
Problem

Given an n × n matrix where isConnected[i][j] = 1 means cities i and j are directly linked, count the number of provinces (connected groups of cities).

Example

Input: [[1,1,0],[1,1,0],[0,0,1]]  ·  Output: 2

  1. Cities 0 and 1 are linked → one province.
  2. City 2 stands alone → second province.
  3. Total distinct roots = 2.
Mental Model
Union each direct link, then count roots. Disjoint Set Union merges connected cities; the number of provinces equals the number of unique set representatives at the end.
Other Approaches
Brute DFS/BFS from each unvisited city — O(n²).
Better Union-Find with path compression and rank — near O(n²·α).
Optimal Approach
  1. Initialize each city as its own parent; start count at n.
  2. For every linked pair i < j, union them and decrement count on a real merge.
  3. Return the final count.
Visual
flowchart LR
  I["each city own set"] --> U["union linked pairs"]
  U --> M{"different roots?"}
  M -- yes --> D["merge; count minus one"]
  M -- no --> U
Code (Java)
private int[] parent;

int findCircleNum(int[][] isConnected){
  int n = isConnected.length;
  parent = new int[n];
  for(int i = 0; i < n; i++) parent[i] = i;

  int provinces = n;
  for(int i = 0; i < n; i++){
    for(int j = i + 1; j < n; j++){
      if(isConnected[i][j] == 1 && union(i, j)) provinces--;
    }
  }
  return provinces;
}

private int find(int x){
  while(parent[x] != x){
    parent[x] = parent[parent[x]];                        // path compression
    x = parent[x];
  }
  return x;
}

private boolean union(int a, int b){
  int ra = find(a), rb = find(b);
  if(ra == rb) return false;
  parent[ra] = rb;
  return true;
}

20Cheapest Flights Within K Stops Medium

Section · Graph Part-II
LeetCode
Problem

Given flights [from, to, price], find the cheapest fare from src to dst using at most k intermediate stops, or -1 if unreachable within that limit.

Example

Input: n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 1  ·  Output: 200

  1. Direct 0→2 costs 500.
  2. 0→1→2 costs 200 and uses exactly 1 stop.
  3. Cheapest within the stop limit is 200.
Mental Model
Bellman-Ford bounded by k+1 relaxations. Each round relaxes edges using only the previous round's distances, so after k+1 rounds you have the cheapest cost using at most k stops.
Other Approaches
Brute DFS all paths under the stop limit — exponential.
Better Dijkstra with a (cost, node, stops) state — O(E log V)-ish.
Optimal Approach
  1. Init dist[src] = 0, others infinity.
  2. Repeat k+1 times: relax all edges using a snapshot of the previous distances.
  3. Return dist[dst] or -1 if still infinite.
Visual
flowchart LR
  I["dist src = 0"] --> R["repeat k plus 1 rounds"]
  R --> E["relax edges from snapshot"]
  E --> C{"more rounds?"}
  C -- yes --> R
  C -- no --> A["answer dist dst"]
Code (Java)
int findCheapestPrice(int n, int[][] flights, int src, int dst, int k){
  int[] dist = new int[n];
  Arrays.fill(dist, Integer.MAX_VALUE);
  dist[src] = 0;

  for(int round = 0; round <= k; round++){
    int[] snapshot = dist.clone();                        // only use last round's values
    for(int[] f : flights){
      int u = f[0], v = f[1], price = f[2];
      if(snapshot[u] != Integer.MAX_VALUE && snapshot[u] + price < dist[v]){
        dist[v] = snapshot[u] + price;
      }
    }
  }
  return dist[dst] == Integer.MAX_VALUE ? -1 : dist[dst];
}
Time O(k · E)
Space O(n)

21House Robber Medium

Section · Dynamic Programming
LeetCode
Problem

Given house values in a row, rob to maximize loot with the constraint that you cannot rob two adjacent houses (adjacent alarms link up).

Example

Input: [2,7,9,3,1]  ·  Output: 12

  1. Rob house 0 (2), skip 1, rob 2 (9), skip 3, rob 4 (1) → 12.
  2. Robbing 7 + 3 = 10 is worse.
  3. Best total is 12.
Mental Model
At each house: skip or take. The best up to house i is max(best[i-1], best[i-2] + val[i]) — two rolling variables capture everything.
Other Approaches
Brute Try every subset with no adjacency — O(2^n).
Better DP array of size n — O(n) time and space.
Optimal Approach
  1. Keep prev2 (best two houses back) and prev1 (best one back).
  2. For each value, cur = max(prev1, prev2 + val).
  3. Shift the window; final prev1 is the answer.

int rob(int[] nums){
  int prev2 = 0;                                          // best up to i-2
  int prev1 = 0;                                          // best up to i-1

  for(int val : nums){
    int cur = Math.max(prev1, prev2 + val);               // skip or rob this house
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}

22Partition Equal Subset Sum Medium

Section · Dynamic Programming
LeetCode
Problem

Decide whether an array of positive integers can be split into two subsets whose sums are equal.

Example

Input: [1,5,11,5]  ·  Output: true

  1. Total is 22, so each side must sum to 11.
  2. {11} and {1,5,5} both reach 11.
  3. A valid equal partition exists.
Mental Model
Reduce to subset-sum of total/2. If the total is odd it is impossible; otherwise a 1-D boolean DP tracks which target sums are reachable using a subset of the numbers.
Other Approaches
Brute Enumerate all subsets checking for half-sum — O(2^n).
Better 2-D DP over items and sums — O(n · sum) space.
Optimal Approach
  1. If total is odd, return false; target = total / 2.
  2. Boolean dp[s] = can we reach sum s; iterate sums downward per number.
  3. Return dp[target].
Visual
flowchart LR
  T{"total odd?"} -- yes --> F["return false"]
  T -- no --> D["dp reach half"]
  D --> N["for each num update dp downward"]
  N --> A["answer dp target"]
Code (Java)
boolean canPartition(int[] nums){
  int total = 0;
  for(int x : nums) total += x;
  if(total % 2 != 0) return false;

  int target = total / 2;
  boolean[] dp = new boolean[target + 1];
  dp[0] = true;

  for(int num : nums){
    for(int s = target; s >= num; s--){                   // downward avoids reuse
      dp[s] = dp[s] || dp[s - num];
    }
  }
  return dp[target];
}

23Unique Paths II (with obstacles) Medium

Section · Dynamic Programming Part-II
LeetCode
Problem

Count the paths from the top-left to the bottom-right of a grid, moving only right or down, where cells marked 1 are obstacles you cannot enter.

Example

Input: [[0,0,0],[0,1,0],[0,0,0]]  ·  Output: 2

  1. The center obstacle blocks the straight diagonal route.
  2. Two ways skirt around it (top-right corner or bottom-left corner).
  3. So there are 2 paths.
Mental Model
Ways into a cell = ways from above + ways from left. Obstacles contribute zero, and a single rolling row keeps space linear.
Other Approaches
Brute Recursive branching at each cell — exponential.
Better Full 2-D DP grid — O(m · n) space.
Optimal Approach
  1. Use a 1-D dp row; seed dp[0] = 1 if the start is clear.
  2. For each cell, zero it if it is an obstacle; else add the left value.
  3. After the last row, dp[n-1] holds the answer.
Visual
flowchart LR
  C["cell"] --> O{"obstacle?"}
  O -- yes --> Z["dp = 0"]
  O -- no --> A["dp += dp left"]
  Z --> N["next cell"]
  A --> N
Code (Java)
int uniquePathsWithObstacles(int[][] grid){
  int n = grid[0].length;
  int[] dp = new int[n];
  dp[0] = grid[0][0] == 1 ? 0 : 1;

  for(int[] row : grid){
    for(int j = 0; j < n; j++){
      if(row[j] == 1){
        dp[j] = 0;                                        // blocked cell
      } else if(j > 0){
        dp[j] += dp[j - 1];                               // from above (dp[j]) + from left
      }
    }
  }

24Best Time to Buy and Sell Stock with Cooldown Medium

Section · Dynamic Programming Part-II
LeetCode
Problem

Given daily prices, maximize profit from multiple buy/sell transactions, but after any sell you must rest one day (cooldown) before buying again.

Example

Input: [1,2,3,0,2]  ·  Output: 3

  1. Buy at 1, sell at 3 → profit 2, then cooldown on day 3.
  2. Buy at 0, sell at 2 → profit 1.
  3. Total profit is 3.
Mental Model
Three states per day: hold, sold, rest. You can only buy from a rest day, and selling forces the next day into rest — the transitions between these states give the recurrence.
Other Approaches
Brute Recurse over buy/sell/cooldown choices — exponential.
Better Memoized (day, holding) recursion — O(n) states.
Optimal Approach
  1. Track hold, sold, rest profits, initialized for day 0.
  2. Each day: hold = max(hold, rest − price), sold = hold + price, rest = max(rest, prevSold).
  3. Answer is max(sold, rest) on the last day.
Visual
flowchart LR
  R["rest"] --> H["hold buy"]
  H --> S["sold sell"]
  S --> R2["rest cooldown"]
  R2 --> H
Code (Java)
int maxProfit(int[] prices){
  int hold = Integer.MIN_VALUE;                           // best profit while holding a share
  int sold = 0;                                           // just sold today
  int rest = 0;                                           // idle / cooled down

  for(int price : prices){
    int prevSold = sold;
    sold = hold + price;                                  // sell what we held
    hold = Math.max(hold, rest - price);                 // keep holding or buy from rest
    rest = Math.max(rest, prevSold);                      // stay resting or cool down
  }
  return Math.max(sold, rest);
}

25Add and Search Word (Word Dictionary) Medium

Section · Trie
LeetCode
Problem

Design a data structure that supports addWord and search, where a search query may contain '.' as a wildcard matching any single letter.

Example

Input: add "bad","dad","mad", then search ".ad", "b.."  ·  Output: true, true

  1. ".ad" matches bad/dad/mad via the wildcard.
  2. "b.." matches bad.
  3. Both searches succeed.
Mental Model
Trie plus DFS branching on dots. Normal letters follow a single child; a '.' forks into every existing child, so wildcard search is a bounded depth-first exploration.
Other Approaches
Brute Store words in a list and regex-match each search — O(N · L) per query.
Better Bucket words by length, then compare — still linear per query.
Optimal Approach
  1. Insert words into a trie of 26-way children with an isEnd flag.
  2. Search recursively: on a letter descend that child; on '.' try all children.
  3. At string end, succeed only if the current node is a word end.
Visual
flowchart TD
  C["current node and index"] --> D{"char is dot?"}
  D -- yes --> A["recurse all children"]
  D -- no --> L["descend matching child"]
  A --> E{"end reached and isEnd?"}
  L --> E
Code (Java)
class WordDictionary {
  private final WordDictionary[] children = new WordDictionary[26];
  private boolean isEnd = false;

  void addWord(String word){
    WordDictionary node = this;
    for(char c : word.toCharArray()){
      int idx = c - 'a';
      if(node.children[idx] == null) node.children[idx] = new WordDictionary();
      node = node.children[idx];
    }
    node.isEnd = true;
  }

  boolean search(String word){
    return dfs(word, 0, this);
  }

  private boolean dfs(String word, int i, WordDictionary node){
    if(i == word.length()) return node.isEnd;

    char c = word.charAt(i);
    if(c == '.'){
      for(WordDictionary child : node.children){
        if(child != null && dfs(word, i + 1, child)) return true;
      }
      return false;
    }
    WordDictionary next = node.children[c - 'a'];
    return next != null && dfs(word, i + 1, next);
  }
}
Time O(26^d · L)
Space O(N · L)

26Search Suggestions System Medium

Section · Trie
LeetCode
Problem

Given a list of products and a search word typed one letter at a time, after each character return up to three lexicographically smallest product names that share the current prefix.

Example

Input: products = ["mobile","mouse","moneypot","monitor","mousepad"], word = "mouse"  ·  Output: suggestions per prefix of "mouse"

  1. Prefix "m" → mobile, moneypot, monitor.
  2. Prefix "mou" → mouse, mousepad.
  3. Prefix "mouse" → mouse, mousepad.
Mental Model
Sort once, then two-pointer narrow the window. With products sorted, each new prefix character only tightens the matching band; take the first three matches at each step.
Other Approaches
Brute Re-scan and filter all products for every prefix — O(n · L) per step.
Better Trie storing up to three suggestions per node — O(L) per step.
Optimal Approach
  1. Sort products lexicographically; set two pointers to the full range.
  2. For each prefix char, advance left past non-matches and pull right in past non-matches.
  3. Collect up to three names in [left, right] for that prefix.
Visual
flowchart LR
  S["sort products"] --> P["add prefix char"]
  P --> N["narrow left and right"]
  N --> T["take first three"]
  T --> P
Code (Java)
List<List<String>> suggestedProducts(String[] products, String searchWord){
  Arrays.sort(products);
  List<List<String>> result = new ArrayList<>();
  int left = 0, right = products.length - 1;

  for(int i = 0; i < searchWord.length(); i++){
    char c = searchWord.charAt(i);
    while(left <= right && (products[left].length() <= i || products[left].charAt(i) != c)) left++;
    while(left <= right && (products[right].length() <= i || products[right].charAt(i) != c)) right--;

    List<String> suggestions = new ArrayList<>();
    for(int j = left; j < Math.min(left + 3, right + 1); j++) suggestions.add(products[j]);
    result.add(suggestions);
  }
  return result;
}
