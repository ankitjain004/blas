01Product of Array Except Self Medium

Section · Arrays
LeetCode
Problem

Given an integer array nums, produce an output array where each position holds the product of every other element. You must avoid the division operator and keep the running time linear.

Example

Input: nums = [1, 2, 3, 4]  ·  Output: [24, 12, 8, 6]

  1. Prefix pass: out = [1, 1, 2, 6] (product of everything to the left).
  2. Suffix pass with running r=1: out[3]*=1 → 6; r=4. out[2]*=4 → 8; r=12.
  3. out[1]*=12 → 12; r=24. out[0]*=24 → 24. Final: [24, 12, 8, 6].
Mental Model
Prefix times suffix. Every answer is the product of all elements to its left multiplied by all to its right. Compute left products in one forward pass, then fold in right products with a single running variable — no extra array, no division.
Other Approaches
Brute For each index, multiply every other element — O(n²).
Division Total product / nums[i], but breaks on zeros — O(n).
Optimal Approach
  1. Fill out[i] with the product of all elements before i (prefix).
  2. Sweep right-to-left with a running suffix product r; multiply it into out[i], then update r *= nums[i].
  3. The output array itself doubles as the prefix store, so space stays O(1) extra.
Visual
flowchart LR
  A["prefix pass: out[i] = product of left"] --> B["suffix pass: r = 1"]
  B --> C["out[i] = out[i] times r"]
  C --> D["r = r times nums[i]"]
  D --> E["answer array"]
Code (Java)
/**
 * Product of every element except self, no division, O(n) time and O(1) extra space.
 * Trick: out[i] = (product of all left) * (product of all right). First pass writes the
 * left products into out; second pass multiplies a running right product r into out.
 */
int[] productExceptSelf(int[] nums){
  int n = nums.length;
  int[] out = new int[n];

  out[0] = 1;
  for(int i = 1; i < n; i++)
    out[i] = out[i - 1] * nums[i - 1];        // product of everything to the left

  int r = 1;
  for(int i = n - 1; i >= 0; i--){
    out[i] *= r;                              // fold in product of everything to the right
    r *= nums[i];
  }
  return out;
}
Time O(n)
Space O(1)

02Move Zeroes Easy

Section · Arrays
LeetCode
Problem

Rearrange an integer array so that every zero is pushed to the end while all non-zero values keep their original relative order. The shuffle must happen in place.

Example

Input: nums = [0, 1, 0, 3, 12]  ·  Output: [1, 3, 12, 0, 0]

  1. w=0. i=0 is 0 → skip. i=1 is 1 → swap into slot 0; w=1.
  2. i=2 is 0 → skip. i=3 is 3 → swap into slot 1; w=2.
  3. i=4 is 12 → swap into slot 2; w=3. Result: [1, 3, 12, 0, 0].
Mental Model
Write pointer for non-zeros. Keep an index w pointing at the next slot that should hold a non-zero value. Scan the array; every time you meet a non-zero, place it at w and advance. Everything after w is automatically zero.
Other Approaches
Brute Build a new array of non-zeros, then pad zeros — O(n) time, O(n) space.
Count then fill Count zeros, shift non-zeros, append zeros — still O(n).
Optimal Approach
  1. Set write index w = 0.
  2. For each i, if nums[i] != 0, swap nums[i] with nums[w] and increment w.
  3. Zeros drift to the tail because they are the only values ever left behind.
Visual
flowchart LR
  S["w = 0"] --> L{"scan i"}
  L -- "nums[i] not zero" --> W["swap nums[i], nums[w]; w++"]
  L -- "nums[i] zero" --> K["skip"]
  W --> L
  K --> L
  L -- done --> R["zeros at tail"]
Code (Java)
/**
 * Move all zeroes to the end in place, preserving order of non-zero elements.
 * Trick: a single write pointer w marks where the next non-zero belongs. Swapping keeps
 * everything stable and never needs extra space.
 */
void moveZeroes(int[] nums){
  int w = 0;
  for(int i = 0; i < nums.length; i++){
    if(nums[i] != 0){
      int tmp = nums[w];
      nums[w] = nums[i];
      nums[i] = tmp;
      w++;
    }
  }
}
Time O(n)
Space O(1)

03Spiral Matrix Medium

Section · Arrays Part-II
LeetCode
Problem

Given an m × n grid, walk its cells in clockwise spiral order — starting top-left, going right, then down, then left, then up — and collect the values into a single list.

Example

Input: [[1,2,3],[4,5,6],[7,8,9]]  ·  Output: [1,2,3,6,9,8,7,4,5]

  1. Top row left→right: 1, 2, 3. top=1.
  2. Right col top→bottom: 6, 9. right=1.
  3. Bottom row right→left: 8, 7. bottom=1.
  4. Left col bottom→top: 4. left=1. Center: 5. Done.
Mental Model
Four shrinking boundaries. Track top, bottom, left, right. Peel one edge at a time and pull the boundary inward. Guard with checks so a single leftover row or column is not traversed twice.
Other Approaches
Direction + visited Turn right when the next cell is out of bounds or seen — O(mn) with a visited grid.
Layer peeling Recurse on the inner sub-matrix — same complexity, more overhead.
Optimal Approach
  1. Set boundaries top=0, bottom=m-1, left=0, right=n-1.
  2. Loop while boundaries valid: traverse top row →, right col ↓, then if rows remain bottom row ←, if cols remain left col ↑.
  3. Move each boundary inward after its pass.
Visual
flowchart LR
  T["top row left to right"] --> R["right col top to bottom"]
  R --> B["bottom row right to left"]
  B --> L["left col bottom to top"]
  L --> S["shrink all four bounds"]
  S --> T
Code (Java)
/**
 * Return matrix elements in clockwise spiral order.
 * Trick: maintain four boundaries and peel one edge per step, shrinking inward. The two
 * inner guards (top <= bottom, left <= right) stop a lone middle row/col repeating.
 */
List<Integer> spiralOrder(int[][] matrix){
  List<Integer> res = new ArrayList<>();
  int top = 0, bottom = matrix.length - 1;
  int left = 0, right = matrix[0].length - 1;

  while(top <= bottom && left <= right){
    for(int c = left; c <= right; c++) res.add(matrix[top][c]);
    top++;
    for(int r = top; r <= bottom; r++) res.add(matrix[r][right]);
    right--;
    if(top <= bottom){
      for(int c = right; c >= left; c--) res.add(matrix[bottom][c]);
      bottom--;
    }
    if(left <= right){
      for(int r = bottom; r >= top; r--) res.add(matrix[r][left]);
      left++;
    }
  }
  return res;
}
Time O(m·n)
Space O(1)

04Rotate Array by K Medium

Section · Arrays Part-II
LeetCode
Problem

Shift every element of an array to the right by k positions, wrapping the tail back to the front. Perform the rotation in place using only constant extra memory.

Example

Input: nums = [1,2,3,4,5,6,7], k = 3  ·  Output: [5,6,7,1,2,3,4]

  1. k %= 7 → 3. Reverse whole array: [7,6,5,4,3,2,1].
  2. Reverse first k=3: [5,6,7,4,3,2,1].
  3. Reverse the rest: [5,6,7,1,2,3,4]. Done.
Mental Model
Triple reversal. Rotating right by k equals reversing the entire array, then reversing the first k and the remaining n-k separately. Each reversal is in place, so no auxiliary array is needed.
Other Approaches
Brute Rotate one step at a time, k times — O(n·k).
Extra array Place each element at (i+k)%n in a copy — O(n) time, O(n) space.
Optimal Approach
  1. Normalize k %= n to avoid redundant full turns.
  2. Reverse the entire array.
  3. Reverse the first k elements, then reverse the last n-k.
Visual
flowchart LR
  A["k = k mod n"] --> B["reverse whole array"]
  B --> C["reverse first k"]
  C --> D["reverse last n minus k"]
  D --> E["rotated array"]
Code (Java)
/**
 * Rotate the array right by k, in place, O(1) extra space.
 * Trick: reverse-all, then reverse the two halves. The full reverse flips order globally;
 * the two partial reverses restore correct order inside each block.
 */
void rotate(int[] nums, int k){
  int n = nums.length;
  k %= n;
  reverse(nums, 0, n - 1);
  reverse(nums, 0, k - 1);
  reverse(nums, k, n - 1);
}

private void reverse(int[] a, int i, int j){
  while(i < j){
    int t = a[i]; a[i] = a[j]; a[j] = t;
    i++; j--;
  }
}
Time O(n)
Space O(1)

05Subarray Sum Equals K Medium

Section · Arrays Part-III
LeetCode
Problem

Count how many contiguous subarrays of nums add up to exactly k. The array may contain negative numbers, so a sliding window will not work.

Example

Input: nums = [1, 2, 3], k = 3  ·  Output: 2

  1. prefix=0, map={0:1}. i=0: prefix=1; need 1-3=-2 → 0 ways. Add {1:1}.
  2. i=1: prefix=3; need 3-3=0 → map has 1 → count=1. Add {3:1}.
  3. i=2: prefix=6; need 6-3=3 → map has 1 → count=2. Subarrays [1,2] and [3].
Mental Model
Prefix sums in a hash map. A subarray ending at i sums to k whenever prefix[i] - k has appeared before. Store the frequency of each prefix sum so far and add up the matches on the fly.
Other Approaches
Brute Try every (start, end) pair and sum — O(n²) or O(n³).
Prefix array Precompute prefixes, still O(n²) to compare pairs.
Optimal Approach
  1. Seed a map with {0: 1} so subarrays starting at index 0 are counted.
  2. Sweep, maintaining a running prefix sum; add map.get(prefix - k) to the answer.
  3. Increment the frequency of the current prefix in the map.
Visual
flowchart LR
  S["map = zero to one"] --> P["prefix += nums[i]"]
  P --> Q{"prefix minus k in map?"}
  Q -- yes --> A["count += freq"]
  Q -- no --> B["skip"]
  A --> U["map[prefix]++"]
  B --> U
  U --> P
Code (Java)
/**
 * Count contiguous subarrays summing to k, handling negatives.
 * Trick: prefix[j] - prefix[i] == k means the subarray (i, j] sums to k. Store how many
 * times each prefix has occurred; for each new prefix, add the count of (prefix - k).
 */
int subarraySum(int[] nums, int k){
  Map<Integer,Integer> freq = new HashMap<>();
  freq.put(0, 1);
  int prefix = 0, count = 0;
  for(int x : nums){
    prefix += x;
    count += freq.getOrDefault(prefix - k, 0);
    freq.merge(prefix, 1, Integer::sum);
  }
  return count;
}
Time O(n)
Space O(n)

06Find All Duplicates in an Array Medium

Section · Arrays Part-III
LeetCode
Problem

You are given an array of length n whose values lie in [1, n], with each value appearing once or twice. Return every value that appears twice, using O(1) extra space.

Example

Input: nums = [4,3,2,7,8,2,3,1]  ·  Output: [2, 3]

  1. Value 4 → index 3 flips to negative. 3 → index 2 negative. 2 → index 1 negative.
  2. Later, value 2 → index 1 already negative → record 2. Value 3 → index 2 already negative → record 3.
  3. Duplicates found: [2, 3].
Mental Model
Use the array as its own hash set. Because values are in [1, n], index |v|-1 can act as a marker. Negate the value at that index the first time; if it is already negative, v is a duplicate.
Other Approaches
Hash set Track seen values — O(n) time, O(n) space.
Sort Sort and scan for adjacent equals — O(n log n).
Optimal Approach
  1. For each value v, compute index idx = abs(v) - 1.
  2. If nums[idx] is negative, abs(v) is a duplicate — add it to the result.
  3. Otherwise negate nums[idx] to mark that value seen.
Visual
flowchart LR
  S["for each v"] --> I["idx = abs(v) minus 1"]
  I --> C{"nums[idx] negative?"}
  C -- yes --> D["record abs(v)"]
  C -- no --> M["negate nums[idx]"]
  D --> S
  M --> S
Code (Java)
/**
 * Return all values that appear twice, using the array itself as a marker table.
 * Trick: values are in [1, n], so index abs(v)-1 is a valid slot. Sign of nums[idx]
 * encodes "seen"; a second visit to a negative slot means a duplicate.
 */
List<Integer> findDuplicates(int[] nums){
  List<Integer> res = new ArrayList<>();
  for(int i = 0; i < nums.length; i++){
    int idx = Math.abs(nums[i]) - 1;
    if(nums[idx] < 0) res.add(idx + 1);
    else              nums[idx] = -nums[idx];
  }
  return res;
}
Time O(n)
Space O(1)

073Sum Closest Medium

Section · Arrays Part-IV
LeetCode
Problem

From an integer array, pick three numbers whose sum lands as close as possible to a target value. Return that closest achievable sum (each element used at most once).

Example

Input: nums = [-1, 2, 1, -4], target = 1  ·  Output: 2

  1. Sort: [-4, -1, 1, 2]. Fix i=-4, lo=-1, hi=2 → sum=-3; best=-3.
  2. sum < target → lo++. lo=1, hi=2 → sum=-1; closer? |−1−1|=2 vs |−3−1|=4 → best=-1. lo++.
  3. Fix i=-1, lo=1, hi=2 → sum=2; |2−1|=1 → best=2. Return 2.
Mental Model
Sort, then fix one and two-pointer the rest. After sorting, each anchor i reduces to a classic two-pointer sweep. Move lo up when the sum is too small, hi down when too big, tracking the closest sum seen.
Other Approaches
Brute Try all triples — O(n³).
Sort + binary search Fix two, binary-search the third — O(n² log n).
Optimal Approach
  1. Sort the array; initialize best to the first three-element sum.
  2. For each anchor i, run two pointers lo = i+1, hi = n-1.
  3. Update best whenever |sum - target| shrinks; move lo/hi toward the target; exit early on exact match.
Visual
flowchart LR
  S["sort array"] --> F["fix anchor i"]
  F --> T["two pointers lo hi"]
  T --> C{"sum vs target"}
  C -- "sum less" --> U["lo++"]
  C -- "sum more" --> D["hi--"]
  C -- "equal" --> E["return target"]
  U --> T
  D --> T
Code (Java)
/**
 * Sum of three elements closest to target.
 * Trick: sort so a two-pointer sweep per anchor is monotone — nudging lo up increases the
 * sum, hi down decreases it. Track the running closest and short-circuit on an exact hit.
 */
int threeSumClosest(int[] nums, int target){
  Arrays.sort(nums);
  int n = nums.length;
  int best = nums[0] + nums[1] + nums[2];

  for(int i = 0; i < n - 2; i++){
    int lo = i + 1, hi = n - 1;
    while(lo < hi){
      int sum = nums[i] + nums[lo] + nums[hi];
      if(Math.abs(sum - target) < Math.abs(best - target)) best = sum;
      if(sum == target) return sum;
      if(sum < target) lo++;
      else             hi--;
    }
  }
  return best;
}
Time O(n²)
Space O(1)

08Two Sum II (Sorted Array) Medium

Section · Arrays Part-IV
LeetCode
Problem

Given a 1-indexed array sorted in non-decreasing order, find the two positions whose values add up to a target. Return their 1-based indices; a unique solution is guaranteed and O(1) extra space is expected.

Example

Input: numbers = [2, 7, 11, 15], target = 9  ·  Output: [1, 2]

  1. lo=0 (2), hi=3 (15) → sum=17 > 9 → hi--.
  2. lo=0 (2), hi=2 (11) → sum=13 > 9 → hi--.
  3. lo=0 (2), hi=1 (7) → sum=9 = target → return [1, 2].
Mental Model
Converging two pointers on sorted data. Because the array is sorted, a sum that is too large means the right value must shrink (hi--), and too small means the left value must grow (lo++). They can never overshoot the unique answer.
Other Approaches
Hash map Works but wastes the sorted property — O(n) time, O(n) space.
Binary search Fix one, binary-search the complement — O(n log n).
Optimal Approach
  1. Place lo at the start and hi at the end.
  2. Compare numbers[lo] + numbers[hi] with the target and move the pointer that corrects the gap.
  3. Return the 1-based indices when the sum matches.
Visual
flowchart LR
  S["lo start, hi end"] --> C{"sum vs target"}
  C -- "too big" --> D["hi--"]
  C -- "too small" --> U["lo++"]
  C -- "equal" --> R["return lo+1, hi+1"]
  D --> C
  U --> C
Code (Java)
/**
 * Two Sum on a sorted array with O(1) space via converging pointers.
 * Trick: sortedness makes the sum monotone in each pointer, so one comparison tells us
 * which side to move. Return 1-based indices as required.
 */
int[] twoSum(int[] numbers, int target){
  int lo = 0, hi = numbers.length - 1;
  while(lo < hi){
    int sum = numbers[lo] + numbers[hi];
    if(sum == target)      return new int[]{lo + 1, hi + 1};
    else if(sum < target)  lo++;
    else                   hi--;
  }
  return new int[]{-1, -1};
}
Time O(n)
Space O(1)

09Merge K Sorted Lists Hard

Section · Linked List
LeetCode
Problem

You are given k linked lists, each already sorted ascending. Splice them into one sorted linked list and return its head.

Example

Input: [[1,4,5],[1,3,4],[2,6]]  ·  Output: [1,1,2,3,4,4,5,6]

  1. Push heads 1, 1, 2 into a min-heap. Pop 1 → append; push its next (4).
  2. Pop 1 → append; push 3. Pop 2 → append; push 6. Continue popping smallest.
  3. Order emitted: 1,1,2,3,4,4,5,6.
Mental Model
Min-heap of list heads. The next global minimum is always one of the k current front nodes. A priority queue keyed by node value lets you pop that minimum and push its successor in O(log k).
Other Approaches
Brute Collect all nodes, sort, rebuild — O(N log N).
Pairwise merge Merge lists two at a time — O(N log k), same as heap.
Optimal Approach
  1. Add each list's head node to a min-heap ordered by value.
  2. Repeatedly pop the smallest node, append it to the tail, and push that node's next if present.
  3. Stop when the heap empties; return the dummy's next.
Visual
flowchart LR
  S["push all k heads"] --> P["pop smallest node"]
  P --> A["append to result tail"]
  A --> N{"node.next exists?"}
  N -- yes --> H["push node.next"]
  N -- no --> C["continue"]
  H --> P
  C --> P
Code (Java)
/**
 * Merge k sorted linked lists using a min-heap of the current front nodes.
 * Trick: the next output is always the smallest of the k list heads. A priority queue
 * gives that minimum in O(log k); each of N nodes is pushed and popped once.
 */
ListNode mergeKLists(ListNode[] lists){
  PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
  for(ListNode node : lists)
    if(node != null) pq.offer(node);

  ListNode dummy = new ListNode(0), tail = dummy;
  while(!pq.isEmpty()){
    ListNode small = pq.poll();
    tail.next = small;
    tail = small;
    if(small.next != null) pq.offer(small.next);
  }
  return dummy.next;
}
Time O(N log k)
Space O(k)

10Sort a Linked List (Merge Sort) Medium

Section · Linked List
LeetCode
Problem

Sort a singly linked list in ascending order. Aim for O(n log n) time and, ideally, constant auxiliary space beyond recursion.

Example

Input: [4, 2, 1, 3]  ·  Output: [1, 2, 3, 4]

  1. Split via slow/fast into [4, 2] and [1, 3].
  2. Sort halves → [2, 4] and [1, 3].
  3. Merge: 1, 2, 3, 4.
Mental Model
Merge sort fits linked lists perfectly. Splitting with a slow/fast pointer and merging two sorted lists are both natural pointer operations, so you get guaranteed O(n log n) without random access.
Other Approaches
Copy to array Dump to array, sort, rebuild — O(n log n) time, O(n) space.
Insertion sort Simple but O(n²).
Optimal Approach
  1. Find the middle with slow/fast pointers and cut the list into two halves.
  2. Recursively sort each half.
  3. Merge the two sorted halves with a dummy-headed splice.
Visual
flowchart LR
  S["split at middle"] --> L["sort left half"]
  S --> R["sort right half"]
  L --> M["merge two sorted"]
  R --> M
  M --> O["sorted list"]
Code (Java)
/**
 * Merge sort on a singly linked list: split by slow/fast, sort halves, merge.
 * Trick: linked lists split and merge in O(1) pointer work, so top-down merge sort is
 * O(n log n) with no random access needed.
 */
ListNode sortList(ListNode head){
  if(head == null || head.next == null) return head;

  ListNode slow = head, fast = head.next;
  while(fast != null && fast.next != null){
    slow = slow.next;
    fast = fast.next.next;
  }
  ListNode mid = slow.next;
  slow.next = null;

  ListNode left  = sortList(head);
  ListNode right = sortList(mid);
  return merge(left, right);
}

private ListNode merge(ListNode a, ListNode b){
  ListNode dummy = new ListNode(0), tail = dummy;
  while(a != null && b != null){
    if(a.val <= b.val){ tail.next = a; a = a.next; }
    else              { tail.next = b; b = b.next; }
    tail = tail.next;
  }
  tail.next = (a != null) ? a : b;
  return dummy.next;
}
Time O(n log n)
Space O(log n)

11Odd-Even Linked List Medium

Section · Linked List Part-II
LeetCode
Problem

Reorder a singly linked list so that all nodes at odd positions come first, followed by the nodes at even positions, preserving their relative order. Use O(1) extra space.

Example

Input: [1, 2, 3, 4, 5]  ·  Output: [1, 3, 5, 2, 4]

  1. odd=1, even=2, evenHead=2. Link 1→3, odd=3; link 2→4, even=4.
  2. Link 3→5, odd=5; even.next is null → stop.
  3. Attach odd tail 5 → evenHead 2. Result [1, 3, 5, 2, 4].
Mental Model
Weave into two chains, then join. Maintain an odd tail and an even tail. Repeatedly hop each pointer two nodes ahead to peel off its parity. Finally connect the odd tail to the saved even head.
Other Approaches
Two lists + concat Build separate odd and even lists — same idea, extra dummies.
Array indices Copy values by parity — O(n) space.
Optimal Approach
  1. Set odd = head, even = head.next, remember evenHead = even.
  2. While even and even.next exist, splice odd.next = even.next then advance odd; likewise for even.
  3. Attach odd.next = evenHead and return head.
Visual
flowchart LR
  S["odd = head, even = head.next"] --> W["weave: odd hops 2, even hops 2"]
  W --> C{"even and even.next exist?"}
  C -- yes --> W
  C -- no --> J["odd.next = evenHead"]
  J --> R["return head"]
Code (Java)
/**
 * Group odd-indexed nodes before even-indexed nodes, in place.
 * Trick: keep two tails (odd, even) and hop each two nodes forward, splicing the chain of
 * its parity. Finally stitch the odd tail onto the saved even head.
 */
ListNode oddEvenList(ListNode head){
  if(head == null || head.next == null) return head;

  ListNode odd = head, even = head.next, evenHead = even;
  while(even != null && even.next != null){
    odd.next  = even.next;
    odd       = odd.next;
    even.next = odd.next;
    even      = even.next;
  }
  odd.next = evenHead;
  return head;
}
Time O(n)
Space O(1)

12Remove Duplicates from Sorted List II Medium

Section · Linked List Part-II
LeetCode
Problem

In a sorted linked list, delete every node that carries a duplicated value, keeping only the values that appear exactly once. Return the head of the cleaned-up list.

Example

Input: [1, 2, 3, 3, 4, 4, 5]  ·  Output: [1, 2, 5]

  1. prev=dummy. 1, 2 unique → advance prev.

/**
 * Delete every value that appears more than once in a sorted list.
 * Trick: a dummy head lets us drop the original head safely. When cur begins a run of
 * equal values, splice the entire run out by pointing prev.next past it.
 */
ListNode deleteDuplicates(ListNode head){
  ListNode dummy = new ListNode(0);
  dummy.next = head;
  ListNode prev = dummy, cur = head;

  while(cur != null){
    if(cur.next != null && cur.val == cur.next.val){
      int dup = cur.val;
      while(cur != null && cur.val == dup) cur = cur.next;
      prev.next = cur;                          // skip the whole duplicated run
    } else {
      prev = cur;
      cur  = cur.next;
    }
  }
  return dummy.next;
}

/**
 * Insert and merge an interval into a sorted, non-overlapping list.
 * Trick: three sequential phases — before, overlapping (widen bounds), after. Sorted input
 * means each interval is visited once.
 */
int[][] insert(int[][] intervals, int[] newInterval){
  List<int[]> res = new ArrayList<>();
  int i = 0, n = intervals.length;

  while(i < n && intervals[i][1] < newInterval[0])
    res.add(intervals[i++]);

  while(i < n && intervals[i][0] <= newInterval[1]){

    newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
    i++;
  }
  res.add(newInterval);

  while(i < n) res.add(intervals[i++]);

  return res.toArray(new int[res.size()][]);
}

/**
 * Search a word along 4-directionally adjacent cells without reuse.
 * Trick: DFS from each candidate start; mark the current cell '#' to forbid revisiting,
 * then restore it on backtrack. Any successful path returns true immediately.
 */
boolean exist(char[][] board, String word){
  int m = board.length, n = board[0].length;
  for(int r = 0; r < m; r++)
    for(int c = 0; c < n; c++)
      if(dfs(board, word, 0, r, c)) return true;
  return false;
}

private boolean dfs(char[][] board, String word, int i, int r, int c){
  if(i == word.length()) return true;
  if(r < 0 || c < 0 || r >= board.length || c >= board[0].length) return false;
  if(board[r][c] != word.charAt(i)) return false;

  char saved = board[r][c];
  board[r][c] = '#';                              // mark as used
  boolean found = dfs(board, word, i + 1, r + 1, c)
               || dfs(board, word, i + 1, r - 1, c)
               || dfs(board, word, i + 1, r, c + 1)
               || dfs(board, word, i + 1, r, c - 1);
  board[r][c] = saved;                            // restore on backtrack
  return found;
}

/**
 * Unique permutations with duplicate values.
 * Trick: sort so equal values are adjacent; at each level use only the FIRST unused copy
 * of a value (skip if nums[i] == nums[i-1] and prev copy is unused). This prunes repeats.
 */
List<List<Integer>> permuteUnique(int[] nums){
  Arrays.sort(nums);
  List<List<Integer>> res = new ArrayList<>();
  backtrack(nums, new boolean[nums.length], new ArrayList<>(), res);
  return res;
}

private void backtrack(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> res){
  if(path.size() == nums.length){
    res.add(new ArrayList<>(path));
    return;
  }
  for(int i = 0; i < nums.length; i++){
    if(used[i]) continue;
    if(i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue;   // skip duplicate sibling

    path.remove(path.size() - 1);
    used[i] = false;

int minEatingSpeed(int[] piles, int h){

/**
 * K points nearest the origin using a size-k max-heap on squared distance.
 * Trick: comparing squared distances avoids sqrt. Capping the heap at k and evicting the
 * farthest keeps only the closest k, in O(n log k).
 */
int[][] kClosest(int[][] points, int k){
  PriorityQueue<int[]> heap =
      new PriorityQueue<>((a, b) -> dist(b) - dist(a));   // max-heap by distance

  for(int[] p : points){
    heap.offer(p);
    if(heap.size() > k) heap.poll();
  }

  int[][] res = new int[k][2];
  for(int i = 0; i < k; i++) res[i] = heap.poll();
  return res;
}

private int dist(int[] p){
  return p[0] * p[0] + p[1] * p[1];
}
Time O(n log k)
Space O(k)

24Task Scheduler Medium

Section · Heaps
LeetCode
Problem

Given task labels and a cooldown n, identical tasks must be separated by at least n intervals. Each task takes one unit of time; find the minimum total time (including idle slots) to finish all tasks.

Example

Input: tasks = [A,A,A,B,B,B], n = 2  ·  Output: 8

  1. Most frequent = 3 (A and B tie). Frames = (3 - 1) = 2 gaps of size (n + 1) = 3.
  2. Skeleton: A ? ? A ? ? A. Fill B into gaps → A B ? A B ? A B.
  3. Length = (3 - 1) · 3 + 2 (tasks tied at max) = 8.
Mental Model
The busiest task sets the skeleton. Arrange the most frequent task with n gaps between copies, then fill the gaps with other tasks. The answer is max(len, (maxFreq - 1) · (n + 1) + countOfMax), where len covers the case with no idling.
Other Approaches
Max-heap simulation Greedily pick the most frequent available task each cycle — O(T log 26).
Optimal Approach
  1. Count frequencies; let maxFreq be the highest and countMax how many tasks hit it.
  2. Compute the skeleton length (maxFreq - 1) · (n + 1) + countMax.
  3. Return the maximum of that value and the total number of tasks.
Visual
flowchart LR
  A["count task frequencies"] --> B["find maxFreq and countMax"]
  B --> C["frame = (maxFreq - 1) times (n + 1) + countMax"]
  C --> D["answer = max(frame, total tasks)"]
Code (Java)
/**
 * Minimum intervals to run tasks with cooldown n, using the greedy frame formula.
 * Trick: the busiest task dictates a skeleton of (maxFreq - 1) blocks of size (n + 1),
 * plus one slot per task that ties the max. If tasks are plentiful, no idling is needed,
 * so the answer is max(skeleton, total tasks).
 */
int leastInterval(char[] tasks, int n){
  int[] freq = new int[26];
  for(char t : tasks) freq[t - 'A']++;

  int maxFreq = 0;
  for(int f : freq) maxFreq = Math.max(maxFreq, f);

  int countMax = 0;
  for(int f : freq) if(f == maxFreq) countMax++;

  int frame = (maxFreq - 1) * (n + 1) + countMax;
  return Math.max(frame, tasks.length);
}
Time O(T)
Space O(1)

25Daily Temperatures Medium

Section · Stack and Queue
LeetCode
Problem

For each day's temperature, determine how many days you must wait until a warmer day. If no warmer day exists, record 0 for that position.

Example

Input: temps = [73, 74, 75, 71, 69, 72, 76, 73]  ·  Output: [1, 1, 4, 2, 1, 1, 0, 0]

  1. Stack holds indices of days awaiting a warmer temp.
  2. At 76 (index 6), it pops 72, 69, 71, 75 → sets their waits (1, 1, 2, 4).
  3. Days 6 and 7 never warm up → 0.
Mental Model
Monotonic decreasing stack of indices. Keep days whose warmer day is still unknown. When a hotter temperature arrives, pop every colder day and record the index gap as its answer — each index is pushed and popped once.
Other Approaches
Brute For each day scan forward for a warmer one — O(n²).
Right-to-left jump Reuse computed answers to skip ahead — O(n).
Optimal Approach
  1. Iterate left to right, maintaining a stack of indices with decreasing temperatures.
  2. While the current temperature exceeds the temperature at the stack top, pop it and set its answer to the index difference.
  3. Push the current index. Remaining stack entries stay 0.
Visual
flowchart LR
  S["stack of indices"] --> R["read day i"]
  R --> C{"temp[i] greater than temp at top?"}
  C -- yes --> P["pop j; ans[j] = i minus j"]
  C -- no --> U["push i"]
  P --> C
  U --> R
Code (Java)
/**
 * Days until a warmer temperature, via a monotonic decreasing stack of indices.
 * Trick: the stack holds days still waiting for warmth. A hotter day resolves all colder
 * days on top at once; the answer is the index gap. Each index is pushed/popped once.
 */
int[] dailyTemperatures(int[] temps){
  int n = temps.length;
  int[] ans = new int[n];
  Deque<Integer> stack = new ArrayDeque<>();

  for(int i = 0; i < n; i++){
    while(!stack.isEmpty() && temps[i] > temps[stack.peek()]){
      int j = stack.pop();
      ans[j] = i - j;
    }
    stack.push(i);
  }
  return ans;
}
Time O(n)
Space O(n)

26Evaluate Reverse Polish Notation Medium

Section · Stack and Queue
LeetCode
Problem

Evaluate an arithmetic expression given in Reverse Polish (postfix) notation. Valid operators are +, -, *, and /, with integer division truncating toward zero.

Example

Input: tokens = ["2", "1", "+", "3", "*"]  ·  Output: 9

  1. Push 2, push 1. See '+' → pop 1, 2 → push 3.
  2. Push 3. See '*' → pop 3, 3 → push 9.
  3. Stack top = 9. Result 9.
Mental Model
Stack of operands. Push numbers; on an operator, pop the two most recent operands, apply the operator (respecting operand order for - and /), and push the result. The final stack value is the answer.
Other Approaches
Recursive tree Build an expression tree, then evaluate — more overhead.
Two stacks (infix) Only needed for infix; postfix needs just one.
Optimal Approach
  1. Scan tokens left to right.
  2. If a token is a number, push it; if it is an operator, pop b then a and push a op b.
  3. Return the single remaining value on the stack.
Visual
flowchart LR
  S["scan token"] --> C{"is number?"}
  C -- yes --> P["push number"]
  C -- no --> O["pop b, pop a; push a op b"]
  P --> S
  O --> S
  S -- end --> R["return top"]
Code (Java)
/**
 * Evaluate a postfix (RPN) expression with an operand stack.
 * Trick: numbers push; an operator pops the two most recent operands. Order matters for
 * '-' and '/': the first popped is the right operand.
 */
int evalRPN(String[] tokens){
  Deque<Integer> stack = new ArrayDeque<>();
  for(String t : tokens){
    switch(t){
      case "+": { int b = stack.pop(), a = stack.pop(); stack.push(a + b); break; }
      case "-": { int b = stack.pop(), a = stack.pop(); stack.push(a - b); break; }
      case "*": { int b = stack.pop(), a = stack.pop(); stack.push(a * b); break; }
      case "/": { int b = stack.pop(), a = stack.pop(); stack.push(a / b); break; }
      default:  stack.push(Integer.parseInt(t));
    }
  }
  return stack.pop();
}
Time O(n)
Space O(n)

27Asteroid Collision Medium

Section · Stack and Queue Part-II
LeetCode
Problem

Asteroids move along a line; positive values head right, negative head left, and the magnitude is their size. When two collide, the smaller explodes (both vanish if equal). Return the state after all collisions settle.

Example

Input: asteroids = [5, 10, -5]  ·  Output: [5, 10]

  1. Push 5, push 10. See -5 → collides with 10; 10 > 5 so -5 explodes.
  2. No further collisions.
  3. Survivors: [5, 10].
Mental Model
Stack, collisions only when right meets left. A collision happens exactly when the stack top is positive and the incoming asteroid is negative. Resolve by comparing magnitudes: pop the loser, and if the incoming one survives, keep checking against the new top.
Other Approaches
Repeated passes Simulate collisions until stable — O(n²).
Optimal Approach
  1. Iterate asteroids, using a stack for the current survivors.
  2. For a negative asteroid, while the top is positive and smaller, pop it; if equal, pop and destroy the incoming too; if larger, the incoming is destroyed.
  3. If the incoming survives all collisions, push it.
Visual
flowchart LR
  S["read asteroid a"] --> C{"top positive and a negative?"}
  C -- no --> P["push a"]
  C -- yes --> M{"compare magnitudes"}
  M -- "top smaller" --> K["pop top; keep checking"]
  M -- "equal" --> D["pop top; drop a"]
  M -- "top larger" --> X["drop a"]
  K --> C
Code (Java)
/**
 * Resolve asteroid collisions with a stack of surviving asteroids.
 * Trick: a collision occurs only when the stack top moves right (positive) and the new
 * asteroid moves left (negative). Compare magnitudes to decide who explodes; a surviving
 * left-mover keeps colliding with the new top.
 */
int[] asteroidCollision(int[] asteroids){
  Deque<Integer> stack = new ArrayDeque<>();
  for(int a : asteroids){
    boolean alive = true;
    while(alive && a < 0 && !stack.isEmpty() && stack.peek() > 0){
      int top = stack.peek();
      if(top < -a){          // top explodes, a continues
        stack.pop();
      } else if(top == -a){  // both explode
        stack.pop();
        alive = false;
      } else {               // a explodes
        alive = false;
      }
    }
    if(alive) stack.push(a);
  }

  int[] res = new int[stack.size()];
  for(int i = res.length - 1; i >= 0; i--) res[i] = stack.pop();
  return res;
}
Time O(n)
Space O(n)

28Remove K Digits Medium

Section · Stack and Queue Part-II
LeetCode
Problem

Given a non-negative integer as a string and a count k, delete k digits so the remaining number is as small as possible. Return it without leading zeros.

Example

Input: num = "1432219", k = 3  ·  Output: "1219"

  1. Build a monotonic stack. Push 1. At 4,3,2 pop bigger predecessors when beneficial: remove 4, then 3.
  2. Continue: remove 2 before the second 2 → k used up.
  3. Remaining digits form "1219".
Mental Model
Monotonic increasing stack, greedy removals. A digit that is larger than the next one is worth removing to shrink a higher place value. Pop while the stack top exceeds the current digit and removals remain; then handle leftover k and leading zeros.
Other Approaches
Brute Try all subsets of removals — exponential.
Recursive greedy Remove the first descent each step — O(n·k).
Optimal Approach
  1. Scan digits; while the stack top is greater than the current digit and k > 0, pop and decrement k.
  2. Push the current digit. After scanning, if k > 0, drop that many from the end.
  3. Strip leading zeros; return "0" if the result is empty.
Visual
flowchart LR
  S["scan digit d"] --> C{"top greater than d and k positive?"}
  C -- yes --> P["pop top; k--"]
  C -- no --> U["push d"]
  P --> C
  U --> S
  S -- end --> T["trim leftover k; strip zeros"]
Code (Java)
/**
 * Remove k digits to form the smallest possible number, via a monotonic stack.
 * Trick: greedily pop a larger digit sitting in a higher place value when a smaller digit
 * arrives. Any leftover k removes from the tail; finally strip leading zeros.
 */
String removeKdigits(String num, int k){
  StringBuilder stack = new StringBuilder();
  for(char d : num.toCharArray()){
    while(k > 0 && stack.length() > 0 && stack.charAt(stack.length() - 1) > d){
      stack.deleteCharAt(stack.length() - 1);
      k--;
    }
    stack.append(d);
  }
  while(k-- > 0 && stack.length() > 0)
    stack.deleteCharAt(stack.length() - 1);

  int i = 0;
  while(i < stack.length() && stack.charAt(i) == '0') i++;
  String res = stack.substring(i);
  return res.isEmpty() ? "0" : res;
}
Time O(n)
Space O(n)
